This chapter is **informative**. Enforceable rules live under the [Platform specification](/platform-spec/).
</Aside>

Beskid packages are not "upload a folder, pick a version number that feels lucky, pray." The **pckg registry** assigns versions; manifests declare **dependencies**; lockfiles make CI reproducible. If that sounds boring, good. We have enough trauma from ecosystems that treat breaking changes as personality.

<Aside type="note">
Package workflows go through `beskid pckg`, which talks to the **pckg** registry service. The command `beskid pkg` (no `c`) does not exist and never has. See the [pckg CLI](/book/18-packages-without-npm-trauma/pckg-cli/) page for the actual subcommands.
</Aside>
