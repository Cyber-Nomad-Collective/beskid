Another billion-dollar mistake is treating **one** memory strategy as moral law. Beskid picks stack activations, a **GC-managed heap**, `ref`/`out`, and rules for fibers. That is documented in [language meta memory model](/platform-spec/language-meta/memory-model/) and realized in [execution runtime memory](/platform-spec/execution/runtime/memory-and-gc-runtime-contract/).

We are not shipping "just use Rust" as the user tutorial. We are shipping **predictable language law** and a collector you can reason about.

<Aside type="tip">

If you want borrow-checker cosplay, use Rust for the compiler host. Write Beskid for the product code the spec actually describes.

</Aside>

Start with the [memory model overview](/book/10-memory-without-billion-dollar-mistake/memory-model-overview/) for locals, heap, and GC, then [stack, heap, and spans](/book/10-memory-without-billion-dollar-mistake/stack-heap-and-spans/) for where things actually live. [Ownership preview](/book/10-memory-without-billion-dollar-mistake/ownership-preview/) covers what we kept from ownership thinking without the borrow checker, and [unsafe and extern preview](/book/10-memory-without-billion-dollar-mistake/unsafe-and-extern-preview/) is an honest look at the FFI boundary.
