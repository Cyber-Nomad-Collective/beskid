A contract in Beskid is not a PDF your manager signs. It is a set of member signatures a type promises to have, checked when the type says it conforms and never again. No vtable, no runtime cast, no `InvalidCastException` at 3 a.m. because a plugin was built against last quarter's interface.

```beskid
use Core.Optional.Option;

pub contract Iterator<T> {
    type Item;
    Option<Item> Current();
    This MoveNext();
}

pub type ArrayIterator<T> : Iterator<T> {
    T[] source,
    i64 index,
    i64 length,

    type Item = T;

    pub Option<T> Current() {
        if this.index >= this.length { return Option::None(); }
        return Option::Some(Array.Get<T>(this.source, this.index));
    }

    pub This MoveNext() {
        if this.index >= this.length { return this; }
        return ArrayIterator<T> { source: this.source, index: this.index + 1, length: this.length };
    }
}
```

That is the corelib's own iterator contract. A generic contract, an associated type, and `This` for "whatever type ends up implementing me". The C# version of this needs `IEnumerable<T>`, `IEnumerator<T>`, a non-generic `IEnumerable` for legacy, and a return type of `IEnumerator<T>` that forgets which concrete iterator you had. Beskid's `MoveNext` returns `ArrayIterator<T>` because that is what `This` means there.

The chapter has four parts. Errors as `Result` values and the `?` operator that moves them. Contracts, including the generic and `This` forms above and the `impl` block for types you do not own. Effects, meaning where compile time ends and runtime begins, and what the compiler will and will not prove about it. And panic, the thing that happens when an invariant is broken and no `Result` can carry the blame.

One warning before you start. The word `contract` also names the compiler mod SDK's `Collector`, `Generator`, and `Analyzer` surfaces in chapter 15. Same keyword, different courtroom. This chapter is the one for user code.
