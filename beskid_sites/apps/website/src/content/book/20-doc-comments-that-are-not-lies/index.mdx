<Aside type="caution">
This chapter is **informative**. Enforceable rules live under the [Platform specification](/platform-spec/).
</Aside>

Documentation lives next to declarations in **`///` line comments**, and nowhere else. No XML novel in a separate pane, no doc assembly step that drifts from the code every sprint. If the comment disagrees with the compiler, the compiler wins.

Chapter 16's [Doc and api.json](/book/16-corelib-batteries-with-opinions/doc-and-api-json/) covers what `beskid doc` generates and how the registry consumes it. This chapter covers the comments themselves: syntax, directives, and how to keep them honest in review.
