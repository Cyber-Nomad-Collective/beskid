A mod is a `type: Mod` package whose compiled artifact plugs into the compiler itself: it can add syntax, raise diagnostics, and rewrite the program before lowering. That is a serious amount of trust to hand a dependency, so mods run compiled and only compiled. There is no `eval`, no interpreted extension path, and no way for a mod to behave one way under the language server and another way under a real build.

The pages that follow: what a mod is and how the host discovers one, the SDK contracts and the `Beskid.Syntax` mirror mods are written against, the Generator/Analyzer/Rewriter roles and what happens when two of them disagree, the pipeline phases a mod runs inside, and the `beskid mod` commands that build and cache the artifact.

Normative Beskid-facing surface: [Compiler Mod SDK](/platform-spec/language-meta/metaprogramming/compiler-mod-sdk/). Host-side law: [Compiler mods](/platform-spec/compiler/compiler-mods/).

<Aside type="danger">

Mods are AOT-only. If you expected `eval` at compile time, you brought the wrong language.

</Aside>
