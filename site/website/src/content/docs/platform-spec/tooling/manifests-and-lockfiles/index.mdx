<SpecSection title="Scope" id="scope">
Formal manifest and lockfile contracts for projects, workspaces, and dependency resolution. Surface syntax for manifest files is **[Bsol (Beskid Structured Object Language)](/platform-spec/tooling/manifests-and-lockfiles/bsol/)**; semantic keys and validation live in the feature contracts below.
</SpecSection>

<SpecSection title="Manifest filenames" id="manifest-filenames">
Project and workspace manifests use dedicated extensions so discovery can distinguish them from legacy names and from Beskid source files.

| Role | Extension | Discovery rule |
| --- | --- | --- |
| **Project manifest** | **`.bproj`** | Exactly one `*.bproj` per project directory; filename **should** match `name` (for example `myapp.bproj` when `name = "myapp"`) |
| **Workspace manifest** | **`.bws`** | Exactly one `*.bws` per workspace root (for example `CoreLib.bws`) |

Legacy **`Project.proj`** and **`Workspace.proj`** are a **hard cut**: tooling **must** reject them with **E1894** and **E1895** respectively and instruct authors to rename to `.bproj` / `.bws`. There is no compatibility shim.
</SpecSection>

<SpecSection title="Named root block" id="named-root-block">
A project manifest **must** declare exactly one **named root block** whose block kind equals the `name` field:

```text
myapp {
  name    = "myapp"
  version = "0.1.0"
  root    = "Src"
}
```

The legacy anonymous `project { ... }` wrapper is **unsupported** (**E1894** at parse time). Reserved top-level block kinds (`target`, `dependency`, `link`, …) **must not** be used as the project root ident.
</SpecSection>

<SpecSection title="Extras and extension keys" id="extras">
Bsol lowering splits known schema fields from **extras**: additional key/value pairs on a block body that the compiler preserves but does not interpret unless a feature contract names them.

| Block | Known fields (non-exhaustive) | Typical extras |
| --- | --- | --- |
| Project root | `name`, `version`, `root`, `root_namespace`, `type`, `readme` | Author or registry metadata not consumed by graph resolution |
| `workspace { }` | `name`, `resolver` | `schema`, **`defaultTestMember`** |
| `member "…" { }` | `path` | `package`, `description`, `category`, `tags` |

**`defaultTestMember`** on the workspace block names the member label used when CLI/LSP resolve a `.bws` path without an explicit `--workspace-member` and without a path under a member tree (for example `beskid test --project CoreLib.bws` selects the `corelib_tests` member in the corelib workspace).

Member **extras** are merged publish/editor metadata; they **must not** replace per-member `.bproj` identity. See **[Workspace and lock contracts — design model](/platform-spec/tooling/manifests-and-lockfiles/workspace-and-lock-contracts/design-model/)**.
</SpecSection>

<SpecSection title="Project kinds at a glance" id="project-kinds">
| `type` | Role |
| --- | --- |
| *(omitted)* | **`Host`** — ordinary application or library project |
| **`Mod`** | Compiler-mod package |
| **`Template`** | Template authoring package |
| **`Aggregate`** | Dependency-only aggregate (no `target` blocks; at least one `dependency`; canonical **`corelib`** uses `type = Aggregate` with shard path deps) |

**`Lib`** targets **may** omit `entry`; assembly discovers modules under `project.root` via workspace scan. **`App`** and **`Test`** targets **must** declare `entry`.

Symbol visibility follows **[Explicit use, no prelude](/platform-spec/tooling/manifests-and-lockfiles/adr/0006-explicit-use-no-prelude/)**: no automatic prelude injection; reachable modules require manifest dependencies and explicit `use` imports.
</SpecSection>
