<SpecSection title="Rationale" id="rationale">
Tooling must be **specified** so different editor plugins, CI images, and third-party drivers agree on flags,
file formats, and protocol extensions without reverse-engineering the reference implementation.
</SpecSection>

<SpecSection title="Background" id="background">
Informative CLI and workflow reference remains in [the Beskid Book](/book/reference/cli/). This domain will absorb normative `spec/` chapters such as
project lockfile and workspace manifest formats as they are promoted from legacy paths.
</SpecSection>

<SpecSection title="Feature index" id="feature-index">
Top-level tooling features appear alongside area hubs below. Highlights:

- **[Formatter](/platform-spec/tooling/formatter/)** — `beskid format` and `beskid_analysis::format`: a canonical, knob-free pretty-printer with idempotent rules and per-construct `Emit` impls.
- **[Foreign library import](/platform-spec/tooling/foreign-library-import/)** — `beskid import lib` and the closed `ExternalLibrary` provider registry that backs v0.3 FFI.
- **[Project scaffolding](/platform-spec/tooling/project-scaffolding/)** — **`beskid new`**, template packages, and **`packageKind: template`**.
- **[Package kinds](/platform-spec/tooling/registry-client/package-kinds/)** — `packageKind: library | template | tool` (the `tool` kind is now Standard, see **D-TOOL-PCKG-0004**).
</SpecSection>
