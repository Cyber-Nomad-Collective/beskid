This article documents **design model** for **type-system pass contract** in the reference compiler.

## What this covers
For newcomers, this page explains where the contract shows up in day-to-day compiler work and which code paths are most useful first reads.

## Anchored code paths
- `compiler/crates/beskid_analysis/src/services/lower.rs` — **`lower.type_check`** is the sole authoritative type pass.
- `compiler/crates/beskid_analysis/src/analysis/rules/staged/type_checking.rs` — structural immutability only (not full typing).
- `compiler/crates/beskid_tests/src/analysis/type_check_diagnostics.rs` — prepare-spine diagnostic code conformance.
- `compiler/crates/beskid_tests/src/analysis/diagnostics.rs` — stable `SemanticIssueKind` → code mapping.

## Type-check placement

Full expression typing runs on the lower spine under phase id **`lower.type_check`**. See [Semantic pipeline / Stage ordering](/platform-spec/compiler/semantic-pipeline/stage-ordering/design-model/) for the split between lower authority and semantic structural checks.

## Practical notes
- Prefer tracing from CLI/test entry points into analysis/codegen crates before changing internals.
- Treat diagnostics and tests as part of the contract, not optional implementation details.
- If behavior changes, update this article and add/adjust tests in `compiler/crates/beskid_tests` or `compiler/crates/beskid_e2e_tests`.
