<SpecSection title="Scope" id="scope">
This area defines how Beskid programs interact with **foreign code** and with the **Rust-hosted runtime** that implements execution services.

**v0.3 FFI** (spec-first, **Standard** in platform-spec) covers **user interop and layout** only. The **runtime ABI** (`BESKID_RUNTIME_ABI_VERSION`, builtin exports) stays on the **[Rust ABI profile](/platform-spec/language-meta/interop/rust-abi-profile/)** and is **not** versioned with user FFI layout bands.

| Feature | Role |
| --- | --- |
| **[Interop.Contracts](/platform-spec/language-meta/interop/interop-contracts/)** | Symbols, call shapes, ownership, callbacks, conformance |
| **[FFI and extern](/platform-spec/language-meta/interop/ffi-and-extern/)** | `Extern` import syntax and attributes |
| **[Export and callbacks](/platform-spec/language-meta/interop/export-and-callbacks/)** | `[Export]` and host callback registration |
| **[C ABI profile](/platform-spec/language-meta/interop/c-abi-profile/)** | Link-time linking, interop views, tier-1 platforms |
| **[Rust ABI profile](/platform-spec/language-meta/interop/rust-abi-profile/)** | Embedding runtime exports (unchanged scope) |
| **[Foreign library import](/platform-spec/tooling/foreign-library-import/)** | `project.link` + CLI `import lib` + `ExternalLibrary` trait |

**Delivery bands:** v0.3.0 — interop views + link-time + export/callbacks (spec). v0.3.1 — `CLayout` primitive structs (Proposed). Complex nested FFI types **after** basic FFI is in place.

Execution chapters under **`/platform-spec/execution/`** document lowering and drivers; they **pair** with this area but do not replace normative language rules here.
</SpecSection>
