<SpecSection title="Normative specification" id="normative-specification">
**Events** provide multicast callbacks **within the fiber that owns the subscription** (fiber affinity). Handlers run on the subscribing fiber's scheduler context unless the program explicitly marshals work elsewhere.

**Cross-fiber** notification (UI loops, console resize, background workers) **must** use **`Channel<T>`** with **Send** / **Receive** from **[Concurrency package](/platform-spec/core-library/concurrency/concurrency-package/)**, not cross-fiber `event` invocation. **`Console`** implements terminal signals via **Channel** (see **[Console terminal events](/platform-spec/core-library/terminal-and-console/console-terminal-events/)**).
</SpecSection>

<SpecSection title="Platform view" id="platform-view">
Runtime helpers (`event_subscribe`, `event_get_handler`, …) remain v0.1 builtins for in-fiber dispatch. New UI and IO stacks should prefer **Channel** endpoints for composability with **Hub** and **spawn**.
</SpecSection>
