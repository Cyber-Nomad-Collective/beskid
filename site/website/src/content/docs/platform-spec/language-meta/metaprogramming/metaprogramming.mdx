<SpecSection title="Language-first model" id="language-first">
Compile-time metaprogramming is anchored on two language-level ideas:

1. **`Mod` project type** — A `Project.proj` whose **project type** is `Mod` participates directly in compiler-mod orchestration: the build discovers the package from the dependency graph, compiles it AOT, and loads mod contracts during host compilation. Schema and wiring details are normative under **[Project manifest contract](/platform-spec/tooling/manifests-and-lockfiles/project-manifest-contract/)**.

2. **Compiler Mod SDK contracts** — Mod behavior is declared by Beskid contracts (`Collector`, `Generator`, `Analyzer`, `Rewriter`, `AttributeGenerator`) over syntax/query facades and typed AST operations. Language-level metaprogramming does **not** include a dedicated `meta` grammar item.
</SpecSection>

<SpecSection title="Contract model (Collector, Generator, Analyzer, Rewriter)" id="pipeline">
Compiler-mod packages define behavior through contracts:

- **Collector** — Declarative entrypoint for selecting target nodes/symbols and constraining scope.
- **Generator** — Incremental by default; emits **typed AST** contributions only (no formatting/text generation contract).
- **Analyzer** — Runs across host code and generated code; reports compiler-native diagnostics and declares rewrites as fixes.
- **Rewriter&lt;TSourceNode, TTargetNode&gt;** — Applies typed replacements with `Result<TTargetNode, FixError> Rewrite(TSourceNode sourceNode)`.
- **AttributeGenerator** — Defines attributes exposed by SDK and mod packages.

All mirrored syntax nodes are expected to implement query/AST-operation contracts surfaced by the SDK so contract code remains declarative.
</SpecSection>

<SpecSection title="Hybrid canonical ownership" id="ownership">
- **[Language meta](/platform-spec/language-meta/)** — `Mod` package contract semantics and user-visible language constraints (for example `extend type` visibility rules).
- **[Language meta / Compiler Mod SDK](/platform-spec/language-meta/metaprogramming/compiler-mod-sdk/)** — Beskid-side SDK contracts and typed syntax/query surfaces.
- **[Compiler / Compiler Mods](/platform-spec/compiler/compiler-mods/)** — Rust-side mod host, AOT artifact lifecycle, phase ordering, typed merge, and incremental scheduling.
- **Compiler-core modularity (Rust)** — Compiler composition / IoC remains Rust-owned and is specified separately under compiler features, not under mod packages.

Neither domain duplicates the other: language pages do not specify Rust algorithms; compiler pages do not redefine Beskid-side mod contract semantics.
</SpecSection>
