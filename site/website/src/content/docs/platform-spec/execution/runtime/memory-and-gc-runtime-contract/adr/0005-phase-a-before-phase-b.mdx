## Context

Parallel GC mutators need write barriers, stack-map coverage, and scheduler coordination. Shipping partial parallel GC risks data races on the Abfall heap.

## Decision

| Phase | Mutators | Ship order |
| --- | --- | --- |
| **A (v0.2)** | One Beskid mutator; many cooperative fibers | **Default ship** |
| **B** | Parallel mutators + real `gc_write_barrier` | **After** normative Phase B text and scheduler updates |

Phase B **must not** land without updating this feature hub and fiber scheduler contracts.

## Consequences

Barriers may be no-ops or simplified while Phase A invariants hold. Fiber/feature docs cross-link Phase tables.

## Verification anchors

GC integration tests; platform-spec Phase diagrams in hub and [design model](../design-model/).
