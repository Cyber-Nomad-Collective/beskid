# beskid 0.4 Readiness Baseline — 2026-07-20

## Decision

beskid 0.4 is not release-ready. The production compiler spine is real and its focused codegen/ISLE suites are green, but the complete source-to-executable route is not yet proven across semantic facts, exhaustive lowering, canonical runtime, exact ABI-v5 kit consumption, clean-prefix Linux execution, portability, and retirement.

## Evidence scope

| Evidence | Result | What it proves | What it does not prove |
| --- | --- | --- | --- |
| Compiler base `25eb8d5`; `cargo test -p beskid_codegen --all-targets` | Passed in the fresh W1 audit | Focused codegen targets pass on the audited compiler base | Full workspace, runtime-kit, or executable correctness |
| Compiler base `25eb8d5`; `cargo test -p beskid_isle --all-targets` | Passed in the fresh W1 audit | Focused generated-ISLE and stock-verification coverage passes | Exhaustive typed-operation coverage or source-owned verifier diagnostics |
| `lower_prepared_syntax_entrypoint` and `lower_syntax_assembly_entrypoint` | Present | A production prepared/assembled-syntax route builds `TypedProgram`, constructs `CodegenInput`, and enters syntax/ISLE lowering | That every language/runtime operation is covered or that all callers avoid legacy paths |
| `FunctionEmissionError::Verification(String)` | Gap confirmed | Stock verifier failures are compilation failures | Originating `AstNodeKey`/span is not retained by verifier errors, so OpenSpec task 2.4 and CYB-14 remain open |
| `compiler/scripts/verify-hir-free-abi-v5.sh` at the current compiler tip | Failed with exit 1 | Active HIR, legacy runtime dependency, and dispatch/fallback findings still block retirement | Its raw match total is not a precise remaining-work count: the broad `DISPATCH_` and `dispatch_(tag|route|envelope)` patterns also count generated/fixture and transitional dispatch definitions |

The superproject currently pins a later compiler descendant than `25eb8d5`; the focused pass above is evidence for the audited base and must not be silently promoted into a fresh full-gate claim for a later pin.

## Platform plumbing versus compiler blockers

| Class | Examples | Readiness interpretation |
| --- | --- | --- |
| Platform/release plumbing | GHCR permissions and package ownership, image build contexts, OpenSpec catalog checkout/drift, Compose interpolation, Coolify staging dependencies | Can make CI or deployment red; does not by itself show that beskid source cannot compile |
| Compiler/runtime authority | Missing semantic facts, incomplete typed-operation inventory, missing AST-owned verifier sites, incomplete canonical runtime, unproven exact-kit attachment and clean-prefix execution | Directly blocks the intended 0.4 source-to-executable contract |

PR #157 decoupled platform delivery from independent OpenSpec, conformance, integration, and security quality checks. Platform health remains required for release delivery, but it must be reported independently from compiler closure.

## Critical path: CYB-5 through CYB-44

1. Close W1 under CYB-5 and CYB-12–15: exhaustive operation inventory, AST-owned verifier diagnostics, and a parsed-project no-legacy integration harness.
2. Close semantic authority under CYB-6 and CYB-16–19: capture/closure facts, spawn legality, non-forgeable runtime intrinsics, completion candidates, diagnostics, and spans.
3. Close exact-kit consumption under CYB-7 and CYB-20–23: exact installed-prefix discovery and manifest/hash/capability validation shared by AOT and JIT/REPL.
4. Finish remaining codegen and LSP migration under CYB-8 and CYB-24–27, with exhaustive inventory and no-legacy regressions.
5. Build the canonical runtime and kits under CYB-9 and CYB-28–34. Establish the first decisive clean-prefix Linux x86-64 compile-and-run proof, then complete macOS arm64 and Windows x86-64 debug/release static/shared coverage.
6. Retire legacy paths under CYB-10 and CYB-35–39. The current red scan is a blocker signal; refine broad dispatch classifications before using its count as a burn-down metric.
7. Run and retain release evidence under CYB-11 and CYB-40–44: full workspace and corelib gates, installed-prefix/package matrix, documentation/OpenSpec closure, GitNexus review, and final sign-off.

## Release claim boundary

The current evidence supports: “the production `TypedProgram` → `CodegenInput` → generated ISLE → stock-verified CLIF spine exists and its focused suites passed at `25eb8d5`.”

It does not yet support: “beskid 0.4 compiles and executes a real program on Linux exclusively through the canonical ABI-v5 architecture,” nor any full 0.4 release claim.
