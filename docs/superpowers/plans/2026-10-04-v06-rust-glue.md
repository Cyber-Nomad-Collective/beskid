# Rust Glue 0.6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver manually proven and equivalently generated Rust import/export integration, with the full required boundary matrix and safe stdio lifecycle on all three release targets.

**Architecture:** Interop.Contracts owns normalized boundary identities, types, ownership and compatibility. Ordinary Beskid code stays on TypedProgram → CodegenInput → ISLE → verified CLIF; Rust emission creates a foreign adapter project, not a Rust translation of the program. One versioned stdio transport joins that adapter to Beskid through Core.IO, existing fibers and cancellation; shared serialization owns value encoding.

**Tech Stack:** Rust 2024 C ABI wrappers, existing Cargo workspace, Beskid corelib/runtime, shared serialization, existing Woodpecker evidence authority.

**Spec:** `docs/superpowers/specs/2026-10-04-beskid-v0-6-release-design.md`, R4 and its R2/R5 dependencies.

## Global Constraints

- Rust Glue is required for 0.6.0; .NET is stretch.
- Targets: Linux x64, macOS arm64 and Windows x64.
- No raw dynamic payload pointers or GC addresses in serialized messages.
- No second scheduler/runtime and no retired HIR/Lowerable entry points.
- Unsupported forms fail before generation; no silent compatibility routes.
- Preserve unrelated user changes; recovery worktree is read-only.
- Root owns normative changes, catalog regeneration and release evidence integration. This document proposes deltas; it does not enact them.
- Before symbol edits, inspect direct source callers/references and report material impact. Before commit, review the exact diff. Ignore GitNexus under the standing goal instruction. Verify actual source if index is stale.

## Review Focus

1. Child stderr floods while stdout contains frames: drain separately and avoid pipe deadlock (Task 3).
2. Cancellation races a completed response or process exit: deliver exactly one terminal result and discard stale replies (Task 6).
3. Foreign buffer carries invalid length, null pointer, overflow or wrong allocator: reject before access; free through its owner (Tasks 2, 5).
4. Tool executable changes after probe or generated path traverses a symlink: fail before execution/materialization (Task 4).
5. Export allocates and collects during request handling: retain valid roots, release them on completion/close (Tasks 5, 6).

### Required matrix

Both import and export directions run each row through manual and generated adapters. Scalars are passed by value. Views are call-scoped borrows copied into bounded wire values; returned views must be copied while their owner remains alive. Transfer buffers require an explicit release symbol and exactly-once release; allocator ownership never crosses implicitly.

| Source/profile | C representation | Policies / cases |
| --- | --- | --- |
| fixed signed i8/i16/i32/i64, unsigned u8/u16/u32/u64 | exact intN_t/uintN_t | Add missing surface primitives through the primitive/compiler owner prerequisite, including parser, semantic, typed/query/ISLE support; min/max/zero, overflow rejection; do not invent i128 obligation |
| f32/f64 | C float/double | Add missing f32 through same prerequisite; finite extrema, NaN, infinities, signed zero; preserve bits on wire and avoid text coercion |
| bool | u8 | only 0/1 valid, reject 2/255; do not emit Rust bool in extern signature |
| char | u32 | Unicode scalar only; reject surrogates and >0x10ffff; encode as scalar, not platform wchar_t |
| UTF-8 view | repr(C) pointer + target-sized length | bounded borrowed bytes, embedded NUL valid, invalid UTF-8 rejected; null permitted only with zero length; no borrowed return surviving owner |
| bytes | repr(C) pointer + target-sized length | borrow and explicit owner-release transfer; empty/null, zero-length nonnull, overflow, bounds, mutation rules |
| unit | void return | forbidden as parameter; no bogus return slot |
| checked opaque handle | u64 slot/generation token | nullability declared; library/session/shape/generation validation; close and stale reuse rejected; never serialize addresses |
| word/native-width | uintptr_t | selected-target width; wire explicit fixed u64 with target range check; all release targets 64-bit; reject mixed target evidence |
| pointer/never, callbacks, variadic, foreign threads, arbitrary records/GC references | no required profile | terminal diagnostic before emission; raw pointer profile needs separate explicit unsafe contract |

Proposed bounded defaults to ratify in OpenSpec: protocol version 1; maximum payload 16 MiB; depth 64; max outstanding requests 256; tool probe timeout 10 s/output 1 MiB; close grace 5 s then terminate/reap. Limits are public contract values, configurable downward; release fixtures exercise exact-limit and limit+1. No silent coercion or unbounded allocations.

## File map and common interfaces

All `compiler/` paths refer to the compiler submodule, `compiler/corelib/` to its own submodule. New names below are proposed interfaces, not claims they exist.

- `crates/beskid_abi/src/interop/glue.rs`: `GlueBinding`, `GlueDirection`, `GluePrimitiveSemantic`, `GlueTransport`, `GlueBindingId`, `GlueOwnership`; use existing TypeShape/InteropSignature/ConformanceEnvelope.
- `crates/beskid_abi/src/interop/glue_protocol.rs`: protocol metadata and validation vocabulary; no scheduler or codec implementation.
- `crates/beskid_abi/src/toolchain/{probe.rs,c_abi.rs}`: bounded explicit tool interrogation and target ABI evidence.
- `crates/beskid_codegen/src/glue/{artifact.rs,rust.rs}`: deterministic artifact model and Rust adapter emitter; backend.rs dispatch only.
- `crates/beskid_analysis/src/mod_host/glue.rs`: typed binding collection and registered contract invocation; `types/result.rs`, `types/checker/contracts.rs`, `analysis/rules/types.rs`: validated binding propagation and exclusivity.
- `crates/beskid_cli/src/commands/{build.rs,syntax_codegen.rs}`: build orchestration/artifact materialization using existing canonical CLI map.
- corelib `packages/glue/src/Core/Glue/{Binding.bd,BridgeSession.bd,BridgeFrame.bd,GlueTag.bd,StdioBridge.bd}` and contracts: Beskid transport/lifetime APIs.
- corelib `packages/foundation/src/Core/Process/{ChildProcess.bd,ProcessError.bd,Process.bd}` and runtime `runtime/beskid/src/Runtime/Host/Process.bd`: child control adapter, delegating host effects only through canonical syscall manifest/ISLE bindings.
- `crates/beskid_tests_interop/{src/interop/glue.rs,fixtures/glue/}`: manual/generated executable corpus.

Shared Rust interfaces: `NormalizeGlueBinding(input: GlueDeclaration, target: TargetMetadata) -> Result<GlueBinding, GlueBindingError>`; `ValidateGlueBinding(binding: &GlueBinding) -> Result<(), GlueBindingError>`; `EmitRustGlue(bindings: &[GlueBinding], evidence: &GlueToolchainEvidence) -> Result<GlueArtifact, BackendError>`; `ValidateGlueArtifact(artifact: &GlueArtifact, root: &Path) -> Result<(), GlueArtifactError>`; `BuildGlueArtifact(artifact: &GlueArtifact, tools: &GlueToolchainEvidence, output: &Path) -> Result<GlueBuildOutput, GlueBuildError>`. Conform naming at implementation to repository rules; do not retain parallel old validation APIs.

`GlueArtifact` contains schemaVersion, backend, target/ABI/layout band, sorted binding identities, sorted relative GeneratedFile(path, bytes, sha256), tool identities, link inputs, expected outputs and artifact digest. Separate deterministic manifest from machine-local resolved tool paths/build log. Hash tool bytes even without expected pin; compare configured pin when present and recheck before spawn. Build output includes actual outputs and digests.

Corelib proposed signatures: `Spawn(ProcessStartInfo) -> Result<ChildProcess, ProcessError>`; child exposes Reader stdout/stderr, Writer stdin, `Wait() -> Result<ProcessExit, ProcessError>`, `Terminate()`, `Close()`. `OpenBridge(BridgeConfig) -> Result<BridgeSession, GlueError>`; `Call<TRequest,TResponse>(BridgeSession, GlueBindingId, TRequest) -> Result<TResponse, GlueError>`; `CloseBridge(BridgeSession) -> Result<unit, GlueError>`. Bind Call to existing fiber cancellation context rather than adding a token/scheduler framework. Serialization owner supplies its final typed codec signatures; require `Encode<T>(value, limits) -> Result<u8[], SerializationError>` and `Decode<T>(bytes, limits) -> Result<T, SerializationError>` semantics, adopting its ratified names in one place.
