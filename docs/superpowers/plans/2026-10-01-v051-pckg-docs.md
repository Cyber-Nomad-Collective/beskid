# Beskid 0.5.1 Package Documentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Browse documentation already present in validated package artifacts, and stop presenting API failures as empty packages.

**Architecture:** Keep full artifact validation and checksum checks, but index only eligible browsable entries. Safe unrelated archive entries are ignored; hidden/traversal docs/source paths remain forbidden. The web page models loading, failure, and genuine empty lists distinctly.

**Tech Stack:** Rust (`beskid_pckg_artifacts`, `beskid_pckg_server`), TanStack React Query in `beskid_sites/apps/pckg`.

**Spec:** `docs/superpowers/specs/2026-10-01-beskid-051-cli-interaction.md` and canonical `openspec/specs/tooling--registry-client--pckg-client-contract/spec.md`.

## Global constraints

- Start compiler from `origin/main` at or after `44a07aed`; use isolated worktrees/branches. No GitNexus, push, merge, publication, credential access, or production mutation.
- Heavy Rust tests run only on the NixOS builder, at most four jobs overall. Debugging should inspect `scripts/diagnose/` and `docs/diagnose.md` if present.
- Preserve validator authority: browser must not accept invalid archives or weaken checksum, traversal, hidden-file, or size limits.
