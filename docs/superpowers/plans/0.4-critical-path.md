## Linux proof definition (acceptance)

A Linux compile-and-run proof is accepted only when all of the following are recorded on one coherent pin pair:

1. Superrepo SHA + compiler SHA.
2. Fresh empty prefix; install exact ABI-v5 kit for `x86_64-unknown-linux-gnu` debug **and** release (static and/or shared as claimed).
3. A real Beskid project (prefer Corelib smoke or a dedicated `hello` using Core.Output) compiles through `TypedProgram → CodegenInput → ISLE → stock-verified CLIF` with no HIR/`Lowerable` construction.
4. JIT Engine run succeeds from that prefix.
5. AOT linked executable succeeds from that prefix.
6. Kit validation fails closed if ABI/version/hash/profile/form mismatched.
7. Commands, logs, and artifact hashes attached to CYB-32 (and linked from CYB-41).
