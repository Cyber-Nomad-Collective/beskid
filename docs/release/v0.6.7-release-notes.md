# beskid 0.6.7 release notes

**DRAFT.** 0.6.7 is not released. The release candidate is root branch
`v067/root-rc2` with compiler `v067/rc2` (`0116bd44`: compiler integration
`bf1ad664`, the version bump and the `beskid doc` generated-unit fix) and
Corelib `5945b13`. Woodpecker has not built it. Platform
evidence below is a placeholder until the three per-platform builds of the
frozen candidate finish. Do not publish or quote these notes as final.

0.6.7 is the last 0.6 release. After it the 0.6 line is frozen and the next
release is 0.7.

0.6.6 was never released: its Linux build failed on a generated Corelib
`Project.lock` in the source inventory. 0.6.7 ships the 0.6.6 work (parallel
execution, transfer classes, incremental collection, Rust Glue extensions; see
`docs/release/v0.6.6-release-notes.md`) together with the 0.6.7 work below.
Where 0.6.7 changes a 0.6.6 rule, the 0.6.7 rule is the one that ships; the
largest change is that `move` is needed only where a value crosses to another
isolate.

## Highlights

- Stable tools. No internal compiler error reaches the user without a code:
  each one is a coded diagnostic at its construct. The language server isolates
  a panic to its request, writes a crash report to `~/.beskid/crash/`, and
  answers every request within a bounded time during a burst of edits.
- One diagnostic model. The CLI and the editor show the same structured
  diagnostic: a short message, the exact span, a code from one registry, help,
  and a quick fix where the repair has one meaning. Parse errors have codes
  `E0101` to `E0117`. `--error-format=json` prints a machine-readable form.
- `move` only at the isolate boundary. A value is moved only when it crosses to
  another isolate (a `Port.Send`, a `move` capture of a `[Captures]`-bounded
  lambda, an isolate spawn). Collection mutators take `mut this`, so
  `list.Push(x);` changes `list` in place.
- Convenient language. Optional parameters with constant defaults and
  caller-information parameters; the conditional expression `cond ? a : b`;
  string and character escapes; `*=`, `/=` and `%=`; numeric literals that take
  their type from the context; contract values with runtime dispatch; primitives
  and `string` that conform to contracts.
- One shared Corelib per toolchain. Projects read Corelib in place from the
  toolchain's sealed bundle instead of copying it into every project.

## What is new

### Language

- Every field declaration in a `type` body ends with `;`
  (`type Point { i32 x; i32 y; }`). A comma is E0115 with a fix. Enum variants
  and literals keep their commas.
- `cond ? a : b`, right-associative, with the C# meaning.
- Optional parameters on functions, methods, contract methods, hosts and
  scopes (E1251 to E1256, E1612). `[CallerFilePath]`, `[CallerLineNumber]` and
  `[CallerColumnNumber]` parameters receive the call site.
- A numeric literal without a suffix takes the type its context gives it; a
  value that does not fit is T0905. Integer literals also take the `_word`
  suffix.
- Contract values: a value of any conforming type is accepted where a contract
  type is expected and dispatches at run time. Primitives and `string` can
  implement contracts (`impl i64 : Formatting`).
- Inline modules are lexical scopes for constants, `use`, functions and types.
  A duplicate name in one scope is one E1102; E1001 and E1006 are retired.
- Tests have their own namespace, use PascalCase names (W1637) and are selected
  by their qualified name (`Topic::Inner`).
- A value function whose end of body is reachable is E1258.
- Growing or shrinking an array through one handle never changes another
  handle. Element writes still reach every handle.

### Runtime

- `Main` is the root fiber and parks like any other fiber. Returning from
  `Main` ends the process even while a detached fiber waits.
- Host hooks (`startup`, scope `init` and `dispose`) run, and scoped
  registrations get a fresh instance set for each `with` activation.
- `Process.Run` searches `PATH` and returns `Ok` for any exit code.
- Every x86_64 target builds for the x86-64-v2 CPU level, and aarch64 for
  Armv8.0-A. The host CPU never adds a feature.

### Corelib

- Corelib tests live in topic modules, and the shared crypto test vectors are
  one set.
- `Assert.Equal<T>` and `Expect.Equal<T>` are generic and show values through
  the `Formatting` contract.
- AEAD `OpenInto` zeroes the output on a bad tag for every provider.

### CLI and tooling

- Log levels, `-v`, `-q`, `--plain`, a progress line on a terminal and clean
  exit on a closed pipe.
- `beskid test` reports `assertion failed: expected 3, found 4` with the call
  site, and `test crashed: <reason>` for a trap. `--json` carries the failure.
- Without `--target`, `beskid build` and `beskid run` never select a Test
  target; `beskid test` runs every Test target.
- `beskid check --all-members` checks every member of a workspace.
- `beskid fmt` never renames an identifier and writes files atomically.
- The VS Code extension selects the toolchain by identity, never runs a
  compiler build found near the workspace, and shows test failures as
  diagnostics at their location. Its version is 0.6.7, as is the Zed
  extension's.
- The tree-sitter grammar parses the 0.6.7 forms: `;` after fields, the
  conditional expression, escapes, default parameter values, numeric literal
  suffixes and a statement `match` without `;`.

### Build and release

- The release gate excludes every generated `Project.lock` from the source
  inventory, which is what stopped the 0.6.6 Linux build.
- The compiler Rust gate runs the workspace tests in parallel and runs the
  staged-evidence tests with `--include-ignored`.
- The `site/learn` playground builds its language server with the
  `release-lsp` profile, so a handler panic does not end the shared server.

## Breaking changes

Beskid has no users yet. These are listed for the record; there is no migration
path. The 0.6.6 breaking changes about `move` and consuming collection
mutators do not ship: 0.6.7 replaces them.

| Change | Effect |
|---|---|
| Fields end with `;` | A comma between `type` fields is E0115. `scripts/migrate/v067_field_semicolons.py` rewrites sources. |
| `Project.lock` format 3 | Any other lock format fails with E3025. Delete the lock and run `beskid dev project lock`. |
| Test names | A test name that is not PascalCase is W1637. |
| Duplicate codes | E1001 and E1006 are retired; a duplicate is E1102. |
| `move` outside a crossing | `move` is for isolate crossings; collection mutators take `mut this`. |
| CPU baseline | x86_64 programs need an x86-64-v2 CPU. |
| Retired features | Lock migration, the `extern_dlopen` allow and deny lists and the `glue-dotnet` placeholder are removed. |
