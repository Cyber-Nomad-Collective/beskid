# beskid 0.6.6 release notes

**DRAFT.** 0.6.6 is not released. The candidate is prepared on branch
`release/v0.6.6` and has not been built by Woodpecker. Platform evidence below
is a placeholder until the three per-platform builds of the frozen candidate
finish. Do not publish or quote these notes as final.

0.6.6 is one release that carries the work planned as 0.6.1 to 0.6.5. There
are no separate 0.6.1 to 0.6.5 releases.

## Highlights

- Parallel execution. `Core.Parallel` runs Beskid code on more than one core.
  The unit of parallelism is the isolate: a runtime instance with its own heap,
  collector and fiber scheduler on its own OS thread. Fork-join scopes, ports,
  pipelines and parallel sequences are built on it.
- Transfer classes. The compiler knows which values can cross between heaps,
  and how: Shared values by pointer, Moved values by hand-over, Copied values
  by copy. Everything else stays where it was made.
- Ownership with `move`. A Moved value has one owner. `move`, destructive reads
  and `exchange` make the hand-over explicit, and the compiler rejects a use
  after a move.
- Incremental garbage collection. Marking runs in bounded steps behind a write
  barrier, and sweeping is lazy.
- More Rust Glue. Records by value, fieldless enums, callbacks and generated
  Rust exports.

## What is new

### Language

- Every type has a transfer class: Shared, Moved, Copied or Never. Primitives
  and `string` are Shared. `T[]` is Moved when `T` is transferable. A nominal
  type takes its class from `[Immutable]`, `[Isolated]` or `[Copyable]` and the
  classes of its fields. A type without a marker, a function value and
  `pointer` are Never. A generic type is classified per instantiation.
- The marker attributes are declared once in `Core.Attributes`. The
  compiler-derived contracts `Transferable`, `Shared`, `Moved` and `Copied`
  live in `Core.Parallel`. A bound `where T: Transferable` is proven from the
  class; E1610 names the reason when it fails.
- Attributes are accepted on every declaration site: functions, methods,
  fields, parameters, lambdas, type parameters, enum variants, constants,
  impl blocks and contract members. Each attribute declares its targets; a use
  on another site fails with E1510.
- `move x` consumes an owning name. `move x.f` is a destructive read that
  leaves the canonical empty value (`None`, an empty array or an empty `List`)
  in the field. `exchange(place, move value)` swaps a field or element and
  returns the old value. `move` on a parameter, or `move this` on a receiver,
  makes it owning.
- Ownership errors E1234 to E1243: use after move, storing a borrowed value,
  consuming in a loop without rebinding, and a destructive read without a
  canonical empty value. `x = f(move x)` rebinds `x`.
- `[Captures(Bound: C)]` on a function-typed parameter or field judges the
  captures of every lambda passed or assigned to it (E1235 to E1238).
- Generic methods: a method declares its own type parameters and `where`
  clause, a member call takes explicit type arguments, and inference reads the
  receiver, the other arguments and the lambda bodies, in that order.
- `__transfer_class<T>()` folds to a constant per instantiation.

### Runtime and memory

- Incremental marking with a hybrid write barrier and lazy sweeping. Generated
  code checks one process word before a store that overwrites a managed field
  or element and calls the barrier only while a collection is marking.
  Initialization stores carry no barrier.
- `BESKID_GC_STRESS` (`alloc`, `alloc:<n>`, `verify`) collects at allocation
  sites and verifies the heap around every collection. The debug runtime kit
  poisons freed slots and keeps them in a quarantine whose size
  `BESKID_GC_QUARANTINE` sets.
- Isolates run on their own threads with their own heaps.
  `BESKID_ISOLATES_MAX` bounds the live isolates; the default is the logical
  processor count. When no isolate is free, a task runs on the caller.
- A finished task's heap is adopted by the isolate that joins it, so a Moved
  result is not copied.
- Ports are bounded queues between isolates, with close, cancel and
  cooperative parking. References from one heap into another are counted
  (modelled on ORCA, the protocol Pony uses) and released by the collector.
- Thread, atomic and processor-count intrinsics on Linux, macOS and Windows.

### Corelib

- `Core.Parallel` (package `corelib_concurrency`): `Parallel.Scope`,
  `Scope.Spawn`, `Scope.SpawnTry`, `Task<T>.Join`, `Scope.Cancel`, `Isolate`,
  `ReadOnlyArray.Freeze`, `Port<T>`, long-lived `Scope.Isolate` workers,
  pipelines (`Source`, `Stage`, `Ordered`, `Sink`) and `ParallelSeq<T>`
  (`List<T>.Parallel()`, `Where`, `Map`, `Chunk`, `MinChunk`, `Collect`,
  `ForEach`, `Count`, `Reduce`, `ReduceUnordered`). The guide and the cost
  table are in `corelib/beskid_corelib/docs/Core/Parallel.md`.
- Collections are `[Isolated]`. Their mutators take `move this`:
  `list = list.Push(v)`.
- `Fiber`, `Channel`, `Hub`, `Mutex`, `MutexGuard`, `WaitGroup` and the socket
  types are `[NeverTransferable]`. Fibers and channels stay inside one isolate.

### Interop (Rust Glue)

- A `[GlueRecord]` type with 1 to 64 scalar fields crosses the C ABI by value.
- A `[GlueEnum]` crosses as its `u32` variant index; an unknown discriminant is
  a checked failure.
- A function type can be a Glue import parameter. The callback is valid only
  during the import call and on the calling thread.
- The Rust owner crate gets a generated `beskid` module with one function per
  consumer export.
- Glue lowers to the Interop.Contracts vocabulary (`glue_type_shape`,
  `glue_interop_signature`).

### CLI and tooling

- `beskid check --project` checks every target of a manifest (App, Lib and
  Test), so a test-only source can no longer pass `check` and then fail at
  `beskid test`.
- LSP: quick fixes insert `move`, mark a parameter `move` or rewrite a store
  as `exchange`; hover shows transfer classes, owning and borrowed bindings
  and capture lists.
- pckg: a file browser for verified package artifacts, and one NodeBB
  discussion thread per package.

### Build and release

- The Linux build packages and uploads its handoff before it exits with the
  release gate status.
- Release bundles no longer carry the Corelib Mod prebuild caches.
- Native Mod cache entries are named by a 32-digit key, which shortens the
  deepest installed path by 32 characters.

## Breaking changes

Beskid has no users yet. These are listed for the record; there is no migration
path.

| Change | Effect |
|---|---|
| Collection mutators consume `this` | `list.Push(v)` without rebinding leaves `list` consumed; use `list = list.Push(v)`. |
| Ownership of Moved values | A use after a consuming use (E1234), storing a borrowed Moved value (E1241) and passing a Moved argument without `move` (E1242) fail. |
| `move` is a keyword | An identifier named `move` must be renamed. |
| Captures across isolates | A task body that captures a Never value fails with E1236. |
| `Reduce` seed | The seed of `Reduce` and `ReduceUnordered` must be Shared or Copied (E1236). |
| Write barrier exports | `beskid_rt_v5_array_write_barrier` is removed; `beskid_rt_v5_gc_write_barrier` replaces it. |
| Native Mod cache key | Cache entries are named by 32 hex digits; 0.6.0 entries are rebuilt. |

## Known limitations

- Platform evidence for the isolate, port and parallel-sequence scenarios has
  been run on Linux x64 only. The macOS and Windows runs are part of the
  release build.
- The benchmarks planned with the parallel work (Savina fork-join and
  ping-pong, data-parallel against the serial loop, the incremental-marking
  pause bound) are not written yet. This release makes no performance claim for
  them.
- Signature help does not show the bindings of a method's own type parameters.
- `Commutative<T>` and `Associative<T>` are claims the compiler does not prove.
- `glue-dotnet` is unavailable, and the Glue stdio bridge stays provisional.
