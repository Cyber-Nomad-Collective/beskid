## 4. Failures (rc12, Linux x86_64)

Interim at writing: the workspace step was in `beskid_engine` (`foundation_io_native`). The counts were 105 passing test binaries, 19 failing binaries and 51 failing tests. Interop, corelib, Mod and package checks were not reached yet. A follow-up commit replaces this section with the final grouping.

### First staging error (root of 19+ failures)

`crates/beskid_e2e_tests/src/harness/cli.rs:117` stages the kit with the removed root command. The first failing test was `beskid_e2e_tests` `tests::aot_smoke::aot_build_and_execute_smoke_fixture`:

```
staging exact debug ABI-v5 runtime kit failed for prefix `/target/v06-release/beskid-e2e-runtime-kits/34d13b279247f14968cf7006ff9d4b0b1038d9630158ab7768a5f693c3aa52db`
stderr:
error: `beskid runtime-kit` was removed; use `beskid dev runtime-kit`. Run `beskid dev runtime-kit --help` for current arguments.
```

That panic poisons the harness staging lock (`cli.rs:85`). Every later e2e test then fails with `runtime-kit staging lock: PoisonError { .. }` (19 at writing). Fix: the harness must invoke `dev runtime-kit` (and any other removed root names). The lock should not stay poisoned after one staging failure; report the staging error to every waiter.

### Collector false positive (query conformance, phase 2)

Repro (cwd `compiler/`, on the builder with the v0.6 env):

```
cargo test --locked -p beskid_cli --bin beskid_cli commands::compiler_mod::tests::rebuilds_sample_mod_through_prepared_syntax_and_writes_registrations
cargo test --locked -p beskid_codegen --test prepared_syntax prepared_syntax_module_lowers_sample_mod_nominal_contract_methods
```

Both fail with `5 semantic errors (first: contract method \`Collector.Collect\` is missing implementation)`. Panic sites: `beskid_cli/src/commands/compiler_mod.rs:385`, `beskid_codegen/tests/prepared_syntax.rs:289`.

Source: `compiler/crates/beskid_tests_mods/fixtures/mods/sample_mod/Src/Mod.bd`. It declares `pub contract Collector { CollectTargetSet Collect(CollectRequest request); }` at line 18. It also declares `pub type SampleCollect : Collector { CollectTargetSet Collect(CollectRequest request) { ... } }` at line 38. The SDK declares a same-named `Collector` in `corelib/packages/compiler-sdk/src/Beskid/Compiler/Collect.bd:119`. Suspects: the phase-2 conformance obligation (E1601) in `beskid_queries/src/semantic_contract/legality/gate*.rs` does not count inline type methods as implementations. Alternatively, it resolves `Collector` to a different declaration (SDK vs local) than the conformance target.
