## Source facts

Compiler baseline: 95c203ff in release worktree. `runtime/beskid/src/Runtime/Dynamic/Dynamic.bd` creates cells by `Alloc(32, null)` then intends payload/descriptor/tag/reserved at offsets0/8/16/24. `Runtime/Mem/Gc/Allocation.bd::Alloc` rejects null descriptors and writes the canonical descriptor to header offset0. Canonical object header owns bytes0..15. Consequently creation is currently rejected; simply substituting a valid descriptor would overwrite its GC header with a payload pointer.

`DynamicCastChecked` compares expected tag directly against offset16 and accepts zero equality. It never consults registration. Both map functions ignore their mapping argument and return the word at offset0 as a raw source pointer. This is source diagnosis, not executed RED evidence.

`runtime_manifest.bsol` declares `BeskidTypeDescriptor` size40/alignment8: size0, alignment8, pointer_map16, pointer_count24, flags32(u32), reserved36(u32). It has no shape tag, stable ShapeId or mapping-plan fields. Dynamic services expose create/wrap(value,descriptor)->pointer, cast(cell,i32)->i32, map_aot/fallback(cell,mapping)->pointer, object_alloc(descriptor)->pointer. There is no canonical shape registration or checked mapping result service.

## Registry ownership ruling proposed to root

Do not multiplex `BeskidRuntimeState.callback_registry` as Dynamic state. It is an existing callback/handler/composition domain with a fixed 1056-byte registry: owner0, callback_count8, handler_count16, composition_container24, callbacks32, handlers544. Callback registration atomically publishes replacement snapshots, copies composition pointer and frees/replaces its registry. Lifecycle shutdown reads composition and frees that exact native size. Extra hidden dynamic fields/overloading callback identities would either disappear during replacement or change ownership semantics silently.

A concrete no-runtime-state-extension route is an explicitly passed registry context rooted through existing collector handles:

- `DynamicRegistryCreate` allocates a managed registry with a canonical frozen descriptor and returns a checked `GcRootHandle`. Compiler-generated host/context owner holds this handle once per active runtime/process; no hidden global or borrowed callback/TLS slot. Service entrypoints receive the registry handle explicitly where needed. Root freezes signatures/layout/version and generation checks.
- Registry fields separately retain owner runtime identity/lifecycle generation, closed flag, local-tag counter and traced shape/mapping lists. Owner runtime pointer is native identity, not a GC pointer-map entry. Counter uses checked nonzero tags with exhaustion rejection; registration compares full stable shape digest and version, not a shortened hash or descriptor pointer identity.
- Registered managed shape records carry their full stable digest/version/local tag, immutable GC descriptor pointer and traced registry ownership/reference. Cell 40 preserves header0/8 and traces payload 16 plus shapeRecord 24; nonzeroTag 32 is checked against registration. Cell→shape→registry keeps metadata alive after external owner handle is released; registry close makes future calls fail while extant cells retain safe descriptor lifetime.
- Shape/plan records and registry are real managed allocations with canonical descriptors and pointer maps. Rooted construction uses GcRootHandle/UnrootHandle or GcRegisterRoot/UnregisterRoot on explicit native slots; rooted source/cell/shape/registry span every allocation. Cyclic managed metadata is collector-owned; no native frees race live cells.
- Canonical GC descriptors/pointer maps for source/destination and registry metadata must have process-image lifetime (compiler-generated immutable data), or an explicit lifetime owner kept until last cell is gone. Dynamic may not synthesize short-lived native descriptor bytes and free them when a registration closes.
- Mapping plan handles resolve real registered managed plan objects under source/destination registry identity and immutable validated conversions. Registry close rejects new calls; generated owner releases its root handle before existing ProcessShutdown demands GcHandlesClear. No requirement to modify the 64-byte runtime state or violate shutdown's external-root invariant.

This is a proposed explicit-context lifecycle contract, not an implemented or accepted ABI layout. Root must decide owner initialization/teardown/injection and perprocess uniqueness, freeze registry/shape/plan descriptors and regenerate matching service/ISLE/codegen contracts before positive fixture implementation. If no explicit-context host owner is provided, registration remains a named prerequisite rather than implicitly placing state into an unrelated field.
