# Required primitive capability implementation map

This source-inspection supplement completes the compiler prerequisite inventory for [the Rust Glue plan](../superpowers/plans/2026-10-04-v06-rust-glue.md), Tasks 1/2 and its required representation matrix. It does not replace that matrix, weaken its 17 representations, or qualify native SDK support. Production remains unchanged during the root query batch. No Cargo was run for this inventory.

## Established gaps

`compiler/crates/beskid_analysis/src/syntax/types/primitive_type.rs` currently has twelve variants: bool/i32/i64/u32/u8/pointer/word/f64/char/string/unit/never. The required additions are i8/i16/u16/u64/f32; there is no requirement to invent i128 or a separate surface usize alias. `word` keeps target-width unsigned semantics. The ABI enum already provides all five representations, and `beskid_codegen/src/isle_adapter/mappings.rs::map_abi_type` already maps their machine widths. Neither establishes source semantics.

The integer grammar only accepts _i32/_i64/_u32/_u8 suffixes. Literal syntax retains exact strings, but suffix selection is a separate, incomplete analysis function. Codegen decimal integer extraction currently parses into i64, whereas hexadecimal extraction parses u64 and casts its bit pattern to i64. Full decimal u64 must therefore gain checked unsigned parsing before bit-pattern delivery to CLIF iconst; changing its declared type alone loses the upper half of the range.

`beskid_isle/src/context/operators.rs::common_integer_operands` currently zero-extends I8 storage and sign-extends other widths. This cannot distinguish i8 from u8 or i16 from u16: extension, comparison, division/remainder, shifts and integer-to-float conversions must use semantic signedness, not CLIF register width. The same file's binary unsigned classifier only recognizes u8/u32/word.

`compiler/corelib/packages/compiler-sdk/src/Beskid/Compiler/Collect.bd` already declares u64 diagnostic/edit offsets. Its generated `Beskid/Syntax/Nodes/PrimitiveType.bd` still mirrors twelve variants. Real SDK compilation and native bridge layout are release prerequisites; unchecked i64 substitution is invalid.

## Red/green and native acceptance

The primitive owner must first add failing source tests, then implement these slices in dependency order: grammar + primitive model → analysis/query identity/ranges/layout → facts/ISLE conversions/operators → interop and SDK generation → actual native Rust Glue equivalence. Existing Rust Glue R4 acceptance remains mandatory.

| PRIM-02 | Decimal and hexadecimal boundary literals for every new integer: min/max/zero, u64 values above i64::MAX, u64::MAX, signed negative minima; reject one-out-of-range and negative unsigned source with diagnostics before lowering. Preserve unsuffixed behavior. |
