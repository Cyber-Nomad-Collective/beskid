# beskid 0.5.4 and 0.6.0: overlap map and merge recommendation

Informative research note (2026-10-11). It compares the 22 compiler commits
`ebcf119b..origin/0.5.4` with the 0.6 line (`ebcf119b..release/v0.6.0` plus the
uncommitted worktree). It is a read-only analysis; no build or test ran for it.
OpenSpec stays normative, Tracker stays the delivery authority.

Recorded 0.6 rulings applied: the `beskid_queries` query layer is the sole
semantic authority of `check`, `analyze` and the LSP (8900f21f; the legacy
`TypeChecker` still builds `SharedTypeResult`, but its diagnostics are purged);
semantic gaps fail closed; contextual typing goes through one `expected_type`
query (decision 2026-10-09); `Core` namespace; per-file Corelib authority
(`corelib_source_paths`).

## Method

- Shared files: `git diff --name-only ebcf119b origin/0.5.4` intersected with
  `git diff --name-only ebcf119b` (worktree included) plus untracked files.
  This gives 106 files on the 0.5.4 side, 915 on the 0.6 side, and 77 in both.
- Size is the sum of added and removed lines per side in the shared files
  (`git diff --numstat`), given as `0.5.4 / 0.6`.
- Conflict severity:
  - **high**: both lines implement the same feature with different designs.
  - **medium**: one feature, but a 0.5.4 fix lands inside a function that 0.6 rewrote.
  - **low**: additive or generated text only.

## 1. Contract dispatch on where-bounded generic receivers

**0.5.4 (570fdd56).**
- Legacy checker: adds `receiver_contract_method`. For a `GenericParam` receiver it searches the
  current function's `function_bounds` and accepts exactly one bound contract that declares the method.
- Queries: `contract_member_receiver` accepts a parameter typed by an enclosing generic. It collects
  `bounded_generic_parameter_declarations`, which reads `FunctionDefinition.where_bounds` only, and a
  bound whose contract does not resolve is skipped silently. It searches the methods of all those contracts.
- `specialization_for_call_in_environment` appends `bounded_generic_witnesses_for_call(...)`, with
  `.unwrap_or_default()` at that call. A failed witness is therefore dropped at issuance, and the
  failure surfaces later as `unavailable("contract_witness")` only if the body calls a contract method.
- No coded diagnostic is issued for an unsatisfied bound.

**0.6 (rc17 where-bound line).**
- `declared_where_bounds` covers function `where` clauses and the enclosing `impl<...> ... where` clause.
  A contract that does not resolve is an error (`where_bound.contract`), not a skip.
- `contract_witnesses_for_call` issues witnesses after substitution is complete. It interprets each bound
  as its applied contract (`T: Serializable<E>` with `E = Wire`) through `applied_contract_arguments` and
  `prove_applied_conformance`. It fails with `generic_bound_not_satisfied` (a coded diagnostic) or
  `where_bound.substitution`.
- `bounded_field_member_receiver` covers `this.element.Read()` on impl-bound fields.
- `validate_current_parameter_witness` re-proves persisted witnesses.
- The multi-bound witness selection is identical to the 0.5.4 change in `contract_method_specialization`.
- The legacy checker is not the authority.

**Judgement.** rustc resolves a method on a type parameter through the `ParamEnv` predicates: all
where-clauses of the item and its parent impl, with generic trait arguments. It rejects unsatisfied
bounds at the call site (E0277), and monomorphization then picks the impl statically. 0.6 follows that
model: impl-level bounds, applied contract generics, an error on failure, re-validation. 0.5.4 covers a
subset, and its `unwrap_or_default` breaks the fail-closed ruling. **Keep 0.6. Do not port 570fdd56 code.**
Keep these tests as evidence:
- `contract_method_bodies.rs::bounded_generic_receivers_dispatch_to_each_instantiation`, which asserts
  two `SizeOf#generic_` specializations and that inference works without explicit type arguments.
- `prepare/tests.rs::bounded_generic_receiver_calls_the_bound_contract_methods`. Re-target it at the
  query diagnostics gate, because legacy diagnostics are purged.

**0.5.4 (708bbe72): a separate, complementary fix.**
- (a) `specialized_receiver_bindings` in `inference.rs`. Inside a specialized body, an explicit receiver
  (`List<T> list; list.Push(v)`) reads its source identity in the enclosing environment. It must prove
  exactly the method owner with matching arity, otherwise the call fails with
  `unavailable_at("call_abi_signature")`.
  The 0.6 `inference.rs` still has only the implicit-receiver reuse and the unspecialized
  `generic_nominal_method_receiver`, so 0.6 has the gap that 0.5.4 fixed.
- (b) `specialized_source_expression_identity` accepts the declaration identifier that a
  `local.Method()` callee hands out. This is absent in 0.6.
- (c) `resolve_type_qualified_local_function`: `List.FromArray<T>(...)` inside the unit that declares
  `List`. This is absent in 0.6.

All three are query-layer and fail closed, which is consistent with 0.6. **Port them as written.**
- The `contracts.rs` hunk applies to the 0.6 body of `specialized_source_expression_identity` with
  only context drift.
- `inference.rs` needs a manual hunk placement: 0.6 reordered witness issuance after substitution.
- Then check (c) against the 0.6 lexical shadowing rules (`lexical_namespace_declares`).

Keep all four `generic_function_bodies.rs` tests, `module_emission_specialization.rs`, and the two
`calls_and_graph.rs` `type_qualified_*` tests.

## 2. Field projections and cross-unit privacy

**0.5.4 privacy (c8bdc7f0).**
- Removes the shared helper. Single-step access hides only hard-coded `Deadline.monotonicNanos` and the
  socket `handle`s, matched by type name.
- Chained projections hide every non-`pub` field of another unit.
- The result is two rules, selected by spelling and by name. A lookalike `Deadline` type in user code
  gets the protected treatment, and a user's private field is readable through `a.b` but not `a.b.c`.
- The only signal is `unavailable(...visibility)`, with no coded diagnostic.

**0.6 privacy (60d0f9fe, E1211).**
- One `field_inaccessible(db, key, declaration, definition, field, PrivateFieldUse)` policy covers
  direct access, every projection step, and struct literals (`Construct`).
- A non-`pub` field is private to its declaring source unit, including inline methods and `extend type`.
- Exceptions are exact Corelib source-path pairs (`canonical_private_field_admission`), proven by
  nominal declaration key and per-file Corelib identity.
- Mod-generated adapters are judged in the target's unit (`contribution_attributed_unit`).
- Legality issues E1211 first. Unsited lowering gaps are given a site and a reason.

**Judgement.** The Rust reference defines field privacy per field, relative to the declaring module,
uniformly for every access form (E0616 for reads, E0451 for literals). 0.6 matches that, and 0.5.4's
name-matched exceptions are the forgery hole that 0.6 closed. **Keep 0.6 and drop c8bdc7f0.** The
0.5.4 commit says Corelib made its time records `pub` instead. Confirm that the 0.6 Corelib Time
records are `pub` or reached only from their declaring unit; the E1211 gate will show it.

**Capabilities 0.6 lacks in the same file.** Combine each one into the 0.6 functions:
- **8223acd3**: `implicit_receiver_field_projection` for a generic enclosing type (`this.inner.count`
  inside `Outer<T>`). 0.6 still returns `None` for a generic owner. 0.5.4 threads
  `enclosing: Option<&GenericSpecializationInstance>`, requires the specialization to bind exactly the
  owner's parameters, and builds shapes and identities from the substitutions. Port it onto the 0.6
  signature, which threads `Option<&Arc<[GenericSubstitution]>>` through `nominal_field_projection_at`.
  Keep the arity check: that is the fail-closed guard.
- **a4fac1b2**: project fields of non-generic call results (`Make().x`). 0.6 still returns `None` for
  every `Expression::Call` target. Port the narrowing, so that only calls with explicit generic type
  arguments keep `applied_call_result_layout`. The projected field must still pass
  `field_inaccessible`.
- **f857c827**: a parameter or local shadows a method-owned field in the single-segment `[field]` arm of
  `field_access_receiver`. In 0.6 the two-segment arms check `is_implicit_receiver_name`, but the
  `[field]` arm does not check `resolve_lexical_declaration`. This is a lexical-scoping correctness fix:
  locals shadow fields, as in C#, Java and Kotlin. Port it.

Tests to keep:
- `method_owned_fields::specialized_generic_method_lowers_a_nested_projection_through_the_implicit_receiver`
- `binding_field_receivers::field_of_a_function_call_result_lowers`
- `layouts_and_enums::parameters_and_locals_shadow_method_owned_fields`
- Add one cross-unit `Make().secret` E1211 case. The 0.5.4 change opens a new read path that the 0.6
  policy must cover.

## 3. Qualified module paths without `use`

**0.5.4 (3763c00b).**
- `fully_qualified_module_unit` runs only when import routing found nothing.
- The target must be the single unit in `visible_module_units(key.unit, generation, path)`.
- Every parent prefix that resolves must list the next segment in `public_module_routes` (`pub mod`).
  A parent prefix that does not resolve is skipped (`continue`).
- Ambiguity returns `None`, so the reference reads as unknown, not as ambiguous.
- There is no lexical shadowing check: an inline module or type named `Core` does not stop the
  absolute lookup.
- The private-module rule applies even inside the parent, so a descendant of a module cannot use the
  absolute path to its private sibling.

**0.6 (470db2bd, OpenSpec `v06-qualified-dependency-paths`).**
- `qualified_module_resolution` returns `Unit | Ambiguous | Missing`. Steps:
  1. Import routes.
  2. A root bound by a `use` expands to that import's logical path.
  3. A root declared lexically (inline module, type, enum, contract) owns the path and never falls
     through.
  4. Otherwise the absolute package-native namespace applies over the project plus the resolved
     dependency closure.
- `absolute_path_crosses_private_module` follows Rust: a private module is reachable only from its
  parent and the parent's descendants.
- Ambiguity is kept apart from absence and reported as E1104 at value paths, type paths and calls.
- Tests: `v06_qualified_dependency_module_paths.rs` (transitive dependency, private item, two-package
  ambiguity, lexical shadowing). The two pre-existing tests are already rewritten exactly as in 0.5.4.

**Judgement.**
- Rust 2018 paths: a crate root resolves without `use`, local names shadow, and ambiguity is a hard
  error (E0659). Privacy is E0603, with the module-and-descendants rule.
- C# and Java also resolve fully qualified names without imports, which is the 0.5.4 citation, but they
  make shadowing explicit (`global::` in C#).
- 0.6 implements all of that. 0.5.4 is a strict subset with three weaknesses: a silent ambiguity, no
  shadowing, and a parent pass when the parent is unresolved.

**Keep 0.6. Do not port the code.** The 0.5.4 helper also calls a different
`visible_module_units` signature and would not compile on 0.6. Port one assertion from 0.5.4
`project_reexports.rs`: `Core.Text.Parser.Private.Hidden()` written fully qualified from outside
`Core.Text.Parser` must stay unresolved. 0.6 only asserts the `use`-routed `Parser.Private.Hidden()`.

## 4. Array literals of calls, fields and enum values

**0.5.4 (2b74d8ef).**
- `literal_element_abi_type` tries the inferred `node_type` first, then a nominal struct literal is
  `POINTER`, otherwise it strips `Expression` and `GroupedExpression` wrappers and takes
  `value_abi_type`.
- A pointer-shaped element must be `GcManaged`; native pointers are rejected.
- All elements must agree on that ABI.

**0.6 (6165a348 and b92aad22).**
- A nominal struct literal keeps the same-declaration rule.
- Every other element uses `value_abi_type`, falling back to `node_type`. `value_abi_type` comes first,
  so a bare literal takes the width of the expected element (`u8[] b = [1, 2]`), as the `expected_type`
  ruling requires. `UNIT` and `NEVER` are rejected.
- Pointer arrays require one uniform `managed_reference_kind`. Native-pointer arrays drop their
  pointer map instead of being rejected.
- Empty literals in a specialization read `expected_type_in_environment(...).array_element_abi_type()`.
- `scalar_layout` covers i8, i16, u16, u64 and f32.

**Judgement.** Contextual typing of literal elements is the checking direction of bidirectional typing:
Pierce and Turner, the rustc `Expectation` for array elements, Swift `ExpressibleByArrayLiteral`
contexts, the TypeScript contextual array type. 0.5.4's `node_type`-first order is synthesis-first: a
`u8[]` context with untyped literals would plan i64 elements. 0.6's order is the recorded ruling.
0.5.4's mixed-kind check (GC only) is stricter but wrong for legitimate native-pointer arrays. **Keep 0.6.**

Port two things:
- The test
  `memory_aggregate_arrays::array_literals_of_call_concatenations_and_enum_values_plan_their_element_abi`
  (a `Piece("a") + Piece("b")` string element and `Shape::Dot` / `Shape::Line(3)` enum elements). It
  confirms that the 0.6 `value_abi_type` sees through the `Expression` wrapper, which 0.5.4 strips
  explicitly. If it fails, normalize with `normalized_expression_node` inside `value_abi_type`, not in
  codegen.
- The bulk half of `array_static.rs` (`bulk_call_element_abi_type`). See section 6.

## 5. Lambdas and function-typed values

**0.5.4 (5883957d, 1209+/118-, 53 files).**
- A function value is a pointer to the existing GC-managed event-handler closure record
  `{header, code@16, env@24}`, and `Type::Function` maps to POINTER.
- A lambda in value position allocates a rooted environment and then the record.
- `CallLowering::FunctionValue`, the `function_value_call` fact and the ISLE `CallKind::FunctionValue`
  emit `call_indirect`, with the environment prefixed when it is non-null.
- `lambda_value_required` keeps immutable callee-only lambda locals inline, with no allocation.
- Untyped lambda parameters take types from the declared function type of the position: an annotated
  local, the enclosing return, or a direct callee parameter.
- In a block-bodied lambda, `return` uses the declared result. This adds a `LambdaExpression` arm in
  `contextual_integer_literal_abi_type`.
- Captures are by-value snapshots. A capture of a `mut` local or a native pointer is E1233
  (`legality/captures.rs`, a query fact).
- Twelve `function_values.rs` tests and two parsed-harness E1233 tests.

**0.6 state.**
- `Type::Function => POINTER` is identical. It was changed in 0.6 independently.
- Inline lambda calls (`calls/closures.rs`, from the base) and spawn closures exist. There is no
  function-value call convention and no `function_values` module.
- The `expected_type` ruling: "a declared return type (never a lambda)". `ReturnStatement` inside a
  lambda is unavailable.
- 0.6 deleted the parent walk in `contextual_integer_literal_abi_type` that 0.5.4 patched, so that
  hunk cannot apply.
- E1232 is `InvalidClifBlock` in 0.6, so E1233 is free on both lines. Confirm it in the OpenSpec
  diagnostic registry.

**Judgement.**
- Flat closure records with a code pointer plus environment are the standard closure-conversion
  representation (Appel, *Compiling with Continuations*; Minamide, Morrisett and Harper,
  "Typed Closure Conversion", POPL 1996), as is the uniform pointer ABI for function types.
- The by-value capture with a mutable-capture rejection is the Java "effectively final" rule. That is
  conservative and sound without boxing, and Swift and Kotlin box instead. It is acceptable for 0.6
  and it fails closed.
- Lambda return and parameter typing from a contextual function type is what Swift, Kotlin and
  TypeScript do, and what rustc does through closure-signature deduction from the expected type.
  It belongs in the checking direction.

**Take 0.5.4, but combine it** so that the 0.6 ruling holds:
1. Extend `expected_type` rather than reviving the deleted walk. Add a `LambdaExpression` context with
   this rule: the expected type of a lambda is a function type `F`; its block-body `return` expects
   `F.result`, and its untyped parameter `i` has type `F.params[i]`. Record this as a refinement of the
   2026-10-09 ruling: "never a lambda" becomes "a lambda only through its own expected function type".
   This is still one query, and parameters stay checked, not inferred from sibling arguments.
2. Move lambda parameter typing in `call_arguments.rs`/`helpers.rs` to the query layer. The legacy
   checker edits carry no diagnostic authority in 0.6. Keep them only if `SharedTypeResult` consumers
   such as hover still need them.
3. Merge the codegen `module_emission` string-pool sharing for lifted entries by hand, because 0.6
   rewrote `orchestration.rs` (152 lines).
4. Keep all twelve `function_values.rs` tests and both E1233 tests. Add a `u8`-returning block lambda
   test to pin the expected-type refinement.

## 6. Bulk calls with generic bulk parameters

**0.5.4 (e9664e4e).**
- Queries: `bulk_call_element_abi_type(call)` specializes `bulk T[]` by the call's substitutions, and
  `inference.rs` (+49) infers `T` from the packed scalar arguments.
- Codegen: `bulk_array_static_plan` uses that query. `array_layout.rs` and `collections.rs` adapt.
- The legacy checker (`call_arguments.rs` 226 lines, `items.rs`, `surface/builder/register.rs`) types
  bulk calls and registers bulk signatures.

**0.6.**
- `bulk_parameter` exists (declared element ABI via `abi_type_from_syntax`, which cannot type `T`).
- `bulk_array_static_plan` reads it from the direct callee, so a generic bulk call fails closed.
- Legality admits any bulk arity (`bulk_parameter_call_with_any_argument_count_is_not_reported`).
- 0.6 rewrote `call_arguments.rs` for other reasons (sibling calls, expected arguments; 310 lines).

**Judgement.** This is the C# `params T[]` / Java varargs model, with generic element inference from
the packed arguments, as `params T[]` infers `T`. The query part is sound and fails closed.
- **Take the query part** (`bulk.rs`, `inference.rs` bulk inference, `queries.rs` export,
  `array_static.rs` bulk branch). Inference must stay synthesis from arguments. It must not read
  `expected_type` of the arguments, which would be the cycle the ruling forbids.
- **Do not take the legacy checker rewrite** unless a 0.6 gate shows that a legacy surface still
  blocks preparation. If it does, take only the minimal `register.rs` signature registration.
- Keep `generic_specialization.rs::parsed_program_packs_generic_bulk_arguments_with_the_call_specialization`.
  Re-target the `inference/tests.rs` and `surface/tests.rs` edits only if their files still assert
  legacy behavior.

## 7. Primitive and string runtime features

All of these are 0.5.4-only behavior. The overlap is generated and runtime files that 0.6 changed
heavily (`abi-v5.json` 12524 lines, `runtime_manifest.bsol` 607, `abi-v5-audit.json` 867).

**String ordering (88143add).**
- Adds `str_cmp` (UTF-8 bytewise, which equals code-point order, as Rust `str: Ord` and Go `<` do),
  `OperatorFact::StringLt/Lte/Gt/Gte`, ISLE dispatch rules, and a legacy checker admission.
- In 0.6, `legality/gate/operators.rs:57` restricts `Lt..Gte` to numeric and bool. Without a change
  there, the query gate rejects string ordering even after the runtime lands.
- Port: the runtime function, the ISLE rules and the codegen operator mapping, plus a one-line change
  to the query gate. Drop the legacy `literals_operators.rs` hunk.

**f64 interpolation (648d5e2a).**
- Adds `str_from_f64_bits` (a shortest round-trip decimal, Ryu/Grisu-class, 408 lines of Beskid in
  `Strings.bd`). The runtime has no float ops, so the value passes as its IEEE bits.
- Port as written, and add f32 through `fpromote` before the call. 0.6 has f32 and 0.5.4 does not.
  Keep the round-trip test.

**Saturating float-to-int (909444b8).**
- NaN gives 0 and out-of-range values clamp, matching Rust `as` (since 1.45), Java and Wasm
  `trunc_sat`. This is the correct choice.
- The 0.6 conversion fact (`calls/facts.rs:45`) admits float to float only, and `operators.rs` has no
  `fcvt_to_*`.
- Port it, but widen the scalar sets to the 0.6 primitive profile:
  - sources: F32 as well as F64;
  - unsigned targets: U16, U64 and WORD as well as U8 and U32;
  - narrowing through I32 for I8, I16, U8 and U16.
  The 0.5.4 helper `debug_assert`s F64 and lists only U8 and U32, so taken verbatim it would mis-sign
  U16 and U64.

**Runtime fixes (abe19020).**
- Empty concatenation: 0.6 already fixed it differently (a one-byte scratch sentinel), so keep 0.6.
- Minimum i64: `StrFromI64` in 0.6 still negates `value`, so `i64::MIN` prints `-`. Port the
  signed-digit loop.
- Bool interpolation: 0.6 still `uextend`s bool to i64 and prints `1`/`0`. Port the `"true"`/`"false"`
  selection.

**Merge method for this group.** Do not text-merge `abi-v5*.json`, `beskid_runtime_abi_v5.h`,
`abi_v5_contract.rs` or `runtime_manifest.bsol`. Add the three runtime entries (`str_cmp`,
`str_from_f64_bits`, and any helper) to the 0.6 manifest source of truth and regenerate with the 0.6
builtin generator. The decision log treats generator closure as authoritative and forbids duplicate
heuristics. Verify that the ABI-v5 audit accepts additive symbols.

Tests to keep: `calls_conversions.rs` (all four `parsed_*` tests). Extend the saturation test with
f32, u16 and u64 targets.

## 8. Small query fixes

- **9c94c662 `this.Method()` sibling calls.** 0.6 resolves unqualified `Method()` siblings (query and
  legacy) but not `this.Method()` in `calls/resolution.rs` and `locals.rs`. The 0.5.4 change checks
  `this` against lexical shadowing. Take it. The 0.6 `locals.rs` edits are in another function
  (literal magnitude), so the conflict is textual only.
  Test: `layouts_and_enums::this_qualified_sibling_call_uses_the_implicit_method_receiver`.
- **8e230afe contextual enum constructors in method arguments.** It extends
  `contextual_enum_constructor_type_path` with `non_generic_callee_parameters`, a second
  callee-parameter lookup for `holder.Pick(Option::None)`. This is the duplicated-context pattern
  that the `expected_type` ruling removed, and the ruling names this function as a separate pending
  slice. **Re-implement** it by letting the argument case of `contextual_enum_constructor_type_path`
  consult `expected_type`, whose `direct_parameter_identity` already covers instantiated nominal
  receivers. Keep the test
  `layouts_and_enums::generic_enum_constructor_takes_its_application_from_a_method_parameter`.
- **b2ea9586 generic-annotated locals.** Codegen `node_walk.rs` falls back to the initializer's scalar
  type for `T first = ...`. That is a codegen-side inference authority that violates
  declared-over-inferred. **Re-implement** it by resolving the annotation `T` through the current
  specialization's substitutions (`generic_abi_type` with the environment) in the query or adapter
  fact. Keep
  `generic_specialization.rs::generic_local_annotated_with_a_type_parameter_lowers_for_scalar_and_string`.

## Suggested merge order

Do not run `git merge origin/0.5.4` wholesale. Port per slice onto `release/v0.6.0`, and keep the
0.5.4 tests as RED-first evidence. Before each slice, cherry-pick the slice's tests and confirm they
fail on 0.6 for the stated reason.

1. **Discard slice (no code)**:
   - 3763c00b, c8bdc7f0 and the 570fdd56 query and legacy code;
   - the 2b74d8ef element ordering;
   - the empty-concat part of abe19020.
   Port their evidence tests (the private-module assertion, the bounded-dispatch tests, the array
   literal test) and confirm that they pass on 0.6. Any failure is a real 0.6 gap.
2. **Query-local fixes**: f857c827, a4fac1b2 and 8223acd3 (projections, with an added E1211
   cross-unit case), then 9c94c662.
3. **Generic specialization**: 708bbe72 (receiver bindings, declared-identifier receivers,
   type-qualified local function), then b2ea9586 re-implemented.
4. **Contextual typing**: 8e230afe re-implemented through `expected_type`.
5. **Runtime and primitives**:
   - the abe19020 minimum i64 and bool fixes, and the corelib `I64ToDecimal`;
   - 909444b8 widened to the 0.6 profile;
   - 88143add with the query gate change;
   - 648d5e2a with f32.
   Regenerate the ABI and manifest once at the end of this slice.
6. **Bulk**: the e9664e4e query and codegen part.
7. **Function values**: 5883957d with the `expected_type` lambda refinement, the OpenSpec delta and
   the E1233 registration. This is last because it is the largest, it touches the most rewritten 0.6
   files, and it depends on slices 4 and 6 (contextual typing, call arguments).

After every slice, run the 0.6 query parity inventory (`entry/parity_*`), the
`beskid_queries` and `beskid_codegen` suites, and the corelib check gate, as the decision log
requires.
