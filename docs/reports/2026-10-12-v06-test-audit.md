# beskid 0.6.0 test audit (read-only, 2026-10-12)

Scope: `compiler/crates/*/tests`, `compiler/crates/*/src/**` test modules, the `beskid_tests_*` crates,
`beskid_e2e_tests`, and the Corelib `.bd` test projects. Rulings applied are those of
`docs/reports/2026-10-04-v06-decisions.md`: the query layer is the sole semantic authority of `beskid check`
(2026-10-09), the legacy `beskid_analysis` `TypeChecker` has no diagnostic authority (it still produces the
executable front end), HIR/Lowerable entry points are retired, there is no `Std` namespace, and Beskid has no
users, so compatibility and migration-hint tests protect nothing. Timings come from `.build/rc26-workspace.log`,
`.build/w2-m-dev-*.log` (`--report-time`) and `.build/rc26-interop.log`.

Classes: DELETE (asserts retired or legacy behavior, exact duplicate, permanently ignored without a live
reason, removed feature), REWRITE (valuable intent on a retired API or authority, brittle, observes an
always-empty internal, or far slower than its claim needs), MERGE (near-duplicates), KEEP.

## Inventory

3 511 Rust `#[test]` functions in 41 crates (largest: `beskid_analysis` 662, `beskid_queries` 569,
`beskid_codegen` 487, `beskid_tests_surface` 273, `beskid_tests_projects` 257, `beskid_cli` 177) plus 667
Corelib `test` blocks in 113 `corelib_tests.bproj` targets and 3 Serialization Mod targets. 36 Rust tests are
`#[ignore]`d in source; `beskid_tests_projects` reports 99 ignored at run time because two macros generate
per-entry bisect helpers. 13 test names are defined twice.

## Brittleness notes (not re-listed above)

- Sleeps in tests: `registry_lock.rs:442` (1 200 ms, item 4), `json_rpc_intellisense.rs:255` (250 ms wait
  for a notification: replace with a polling read of the response queue), `abfall/tests/gc_functional.rs:69`
  (200 ms), `native_harness.rs:243,253` (2 s/30 s inside killed child probes: fine), poll loops of 1-20 ms
  elsewhere (fine).
- Exact-text assertions on diagnostics are the norm in `beskid_tests_interop` and the CLI tests
  (`contains("beskid dev mod rebuild")`, `contains("unknown import path ...")`). They are acceptable while
  the codes are stable; prefer the `[E1234]` code prefix over the sentence where both are present.
- `library_target.rs`, `incremental.rs`, `json_rpc_intellisense.rs` are the slowest live tests (280-583 s);
  they are KEEP here because the stable Corelib root work already targets them.
