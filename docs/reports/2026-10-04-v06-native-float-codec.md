# Native float codec design and compiler seam

The required BSOL representation remains finite decimal f32/f64, preserving negative zero and exact declared width. Generic DataValue retains IEEE bits; bit-hex strings are not a substitute wire representation.

The primary [Ryū implementation and correctness paper](https://github.com/ulfjack/ryu) establish shortest roundtrip formatting using fixed-size integer operations. Its [double formatter](https://github.com/ulfjack/ryu/blob/master/ryu/d2s.c) is a suitable native-port reference, retaining its license notice. The primary [fast_float implementation](https://github.com/fastfloat/fast_float) specifies direct correctly rounded parsing into float or double, including ties to even. Its [digit-comparison fallback](https://github.com/fastfloat/fast_float/blob/main/include/fast_float/digit_comparison.h) uses bounded significant digits and exact integer comparisons against halfway values; discarded nonzero digits must retain sticky information. A native implementation must establish its retained-digit bound from the format constants/proof rather than guessing one. Ordinary float multiply/divide accumulation is not equivalent.

The initial compiler audit exposed value conversions through `semantic_contract/calls/facts.rs::primitive_numeric_conversion_tracked`, and `beskid_isle/context/operators.rs` uses signed/unsigned numeric conversion instructions. That initial path did not prove bit reinterpretation. The compiler-owned foundation is `Core.Numeric.FloatBits.ToBits32(f32)->u32`, `FromBits32(u32)->f32`, `ToBits64(f64)->u64`, `FromBits64(u64)->f64`, with exact trusted source identity, semantic facts and stock-verifier-clean ISLE bitcast lowering. Tests must preserve both zeros, all subnormal boundaries and NaN payload bits. BSOL itself rejects nonfinite numbers, while generic storage and Glue preserve their bits.

Core.Serialization.FloatDecimal should operate on raw bits with `Format(bits,width,limits)->Result<string,SerializationError>` and `Parse(text,width,limits)->Result<u64,SerializationError>`. No host float parser/formatter forwarding is allowed. Formatting uses exact shortest interval selection or a licensed native Ryū port; parsing directly rounds to the requested format, never decimal→f64→f32. Exponent/digit counters and allocations are checked before work. Long decimals, leading zeros and huge signed exponents must have documented finite bounded behavior, preserving negative zero on underflow where rounding yields zero. Unicode digits, whitespace, trailing garbage, NaN/Infinity and overflow reject. Native vectors include min/max normal/subnormal, powers of two, both zeros, direct-f32 double-rounding traps, halfway-even/odd neighbors, all 9/17 significant-digit roundtrips and one-byte-over limits.

This report is source/research evidence, not native qualification. FloatDecimal production is now implemented as an exact integer-rational candidate: requested-width binary search and midpoint ties-to-even parsing, and shortest 9/17-digit candidate search using exact ratios and native parse roundtrip verification. Long mantissas use the primary fast_float format bounds (769 f64 / 114 f32 significant digits) plus its nonzero sticky-digit strategy. Candidate source parses successfully; five native test cases are authored, with semantic and runtime qualification pending. Root subsequently reports the exact FloatBits services implemented with 18 ISLE/JIT vectors passing in two tests; those gates do not qualify the decimal codec. The existing BSOL Parser only screens finite numeric range and is not the typed codec.

A subsequent exact rational/IEEE diagnostic found a shortest-output counterexample at 2^-1017 (bits `0x0060000000000000`): nearest 16-digit candidate `7120236347223044e-322` does not roundtrip, while `7120236347223045e-322` does. At power-of-two boundaries the two rounding half-intervals differ. The candidate formatter now checks the nearest decimal and both adjacent integer candidates at each precision, using its native exact parser to enforce interval inclusion and tie behavior. A dedicated native expected-string case is authored but unrun; the diagnostic used Python Fraction/IEEE as a research reference only, with no host conversion in production.
