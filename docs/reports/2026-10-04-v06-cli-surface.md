## Windows dependency transaction prerequisite

This is a source/API-contract review, not Windows execution evidence. The 13 generic transaction cases passed on macOS under root coordination; they do not qualify Windows security, namespace durability, or recovery. No transaction production source was changed during this review.

The current Windows branch opens directories read-only with BACKUP_SEMANTICS and calls sync_all. Microsoft requires GENERIC_WRITE for FlushFileBuffers; opening a directory correctly is not evidence that directory namespace changes can be durably flushed on the supported filesystem. The existing branch needs a native failing/passing test before any durability claim. A volume flush requiring administrator privileges is unsuitable as the ordinary CLI implementation. [FlushFileBuffers contract](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers), [CreateFileW directory and access contract](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew).

Windows CheckOwner is currently a no-op; private directory creation/checking has no DACL policy. StagePublished copies Rust Permissions, which supplies no original security descriptor snapshot, and journal schema 1 stores only bytes plus replacement identity. Rollback obtains permissions from the current destination. Consequently the implementation cannot demonstrate preservation/restoration of original owner/DACL or private journal access. Windows objects created without an explicit security descriptor inherit their parent's security, while moved files retain their original descriptor. Private staging inheritance must therefore not become the descriptor of a newly published public lock. [File security and access rights](https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights).

Windows identity currently consists of creation time, write time and length. Recovery needs volume serial number plus file ID obtained from a handle, together with bytes; timestamp-equivalent external replacement must not be overwritten. Handle-based inspection should reject reparse points and check the staging/project volume rather than relying solely on Rust symlink classification and the Unix-only device check. [FILE_ID_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info), [GetFileInformationByHandleEx](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getfileinformationbyhandleex).

The shared analysis owner should introduce a Windows platform boundary beneath the existing paired transaction state machine, rather than scatter unsafe calls through planner/editor services. Proposed boundary operations are secure private creation/validation, handle-based file identity and state capture, closed-handle staged publication, and qualified durable publication/removal. A Windows-only implementation module and target-specific native API dependency should contain handle ownership, descriptor allocation and error translation. Preserve existing Unix behavior and the public Plan/Commit interfaces.

Required implementation sequence:

1. Capture original file security/state before staging, journal a bounded, versioned representation, and restore that captured state during rollback. Define explicitly which attributes, timestamps and alternate streams are retained; unsupported preservation must fail before publication rather than silently disappear. Original absence remains a distinct journal state.
2. Create the private directory with an explicit protected descriptor atomically; validate existing ownership and allowed access on opened handles. Reject foreign or broadly accessible existing private state instead of silently taking ownership. A new public Project.lock must receive ordinary project-parent creation policy, not the private staging policy. Security fixtures require no credential transfer or administrator mutation.
3. Replace timestamp identity with volume/file ID and verify ordinary files, containment and same-volume publication through native handles. Revalidate immediately before publication/recovery to preserve external edits.
4. Choose the replacement primitive together with its recovery protocol. ReplaceFileW preserves selected destination metadata and produces the replacement file's ID, but its write-through flag is unsupported and documented errors can leave intermediate names. It therefore requires a backup-aware journal, closed staging handles, and explicit handling of partial outcomes; merely substituting it for fs::rename is incomplete. Never ignore ACL merge errors. [ReplaceFileW contract and failure states](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew).
5. Establish a supported, non-administrator durability protocol on native Windows storage. Do not treat an unsupported directory flush as successful. Separate process-crash recovery evidence from power-loss durability; if the proposed primitive cannot meet the latter, retain this release blocker until a documented protocol and native fault evidence exist.

The root-owned Windows test slice should include these acceptance cases, running against real local Windows filesystems under a normal user token:

| ID | Native gate and required observation |
| --- | --- |
| WINDEP-01 | Existing-lock and absent-lock success reach a consistent pair; each actual publication/journal flush succeeds without elevation. |
| WINDEP-02 | Explicit protected/custom public DACL and owner survive commit and injected rollback; original attributes/state selected in the preservation contract survive too. New lock inherits project creation policy rather than private staging ACL. |
| WINDEP-03 | Broad parent inheritance does not expose journal/stages/guard; restart validates the private descriptor. Foreign or unsafe pre-existing private directories fail without changing public files. |
| WINDEP-04 | Junction/reparse-point project, staging and destination fixtures fail closed; outside sentinel files remain unchanged. Fixture setup failure is a failed prerequisite, not a skipped acceptance. |
| WINDEP-05 | A lock opened without delete sharing causes replacement failure after manifest publication; bytes and original security state roll back, or a complete private recovery journal remains. |
| WINDEP-06 | After interrupted publication, substitute another file with identical bytes/length/timestamps but a different file ID. Recovery refuses to overwrite it and preserves both destinations. |
| WINDEP-07 | Inject documented native partial publication states, file/directory flush failures, and committed-journal cleanup failure; restart either restores the complete original pair or recognizes the complete committed pair without overwriting external state. |
| WINDEP-08 | Kill child processes at durable Prepared, first publication, second publication and committed-journal boundaries; recover actual bytes and security state. Child-process termination alone is not a power-loss test. |
| WINDEP-09 | An isolated Windows VM/storage fault test demonstrates acknowledged journal discovery and pair recovery after power interruption at the same boundaries. Record filesystem, native target, source SHAs and candidate checksums. |
