## D06-01: Dependency correctness reconciliation

Evidence: released `beskid_analysis/src/projects/workflow/registry.rs` rejects
unavailable requested coordinates and records/checks artifact and materialized
tree identities. The old checkout's fallback and missing-digest findings are
superseded. Remedy: keep the one project-graph resolver, add regression fixtures,
and build add/remove/selective-update as comment-preserving transactions over it.
Avoid a second resolver or unnecessary integrity rewrite. Bare registry selection
does not depend on response ordering: select the highest stable SemVer precedence,
break equal precedence by the full coordinate, and reject malformed, duplicate or
yanked entries. Explicit prerelease coordinates remain supported without invented
range semantics. Three behavioral failures were observed before this correction;
`cargo test -p beskid_analysis --lib v06_selection_tests` now passes all three
tests with zero failures or ignores. The pure manifest editor passed all nine integration
cases with no skips: CRLF/comments/Unicode preservation, exact selected-version
edits, duplicate/source conflicts and deterministic project selection. Affects R1
and CLI/DEP acceptance cases. Status: editor verified; transactional workflow and
installed CLI verification remain pending.

## D06-02: Native typed generation prerequisite

Evidence: current native Mod invoker delegates generator results to stub
contribution materialization; required serialization adapters need real typed
structural contributions and generation-bound semantic queries. Alternative:
source-text generators or dynamic-only serialization would bypass the accepted
architecture. Remedy: implement native ownership/materialization and structured
emitter/shape query, with fail-closed missing-artifact and stale-handle cases,
then statically specialized generic adapters. Affects R2, R3 and Glue generation.
Status: required production execution tests and implementation pending.

## D06-03: Dynamic runtime correctness prerequisite

Evidence: current Dynamic.bd initializes shape zero, passes no allocation
descriptor and ignores mapping. Null descriptors alone do not prove a GC defect.
Remedy: first reproduce checked-cast/mapping and forced-GC behavior, then register
traced descriptors and construct fresh destination values using validated mapping.
Do not return the original payload as successful mapping or enable unrestricted
reflection. Affects DYN and serialization. The new Dynamic fixture initially
failed before behavior tests because the compiler's exact fixture allowlist omitted
it. Adding its embedded source now passes all five authority tests, including
source/manifest tampering and copied-project rejection. This admits the canonical
test only; behavior reproduction and checked mapping implementation remain pending.

## D06-04: Shared grammar and migration corrections

Evidence: actual Pest syntax uses `@Name(args)`, while v2 prose shows bracket
attributes; quoted strings lack escape decoding, maps require an entry, list
items omit numeric literals, and scalars lack signed/finite-decimal forms.
Current migration implementation uses text replacement/search. Remedy: ratify
canonical @ syntax and explicit bounded numeric/escaped-string additions, then
shared Rust/native corpus and structural migrations with collision/route errors.
Preserve full syntax/profile semantics rather than replacing BSOL with a data map.
Affects R3 and CLI source edits. Status: normative change in progress.

## D06-05: Primitive and process prerequisites for Rust Glue

Evidence: actual primitive vocabulary omits f32 and several fixed integer widths;
SDK source nevertheless references u64. Core.Process currently supplies Id/Exit
but lacks child spawn/pipes/wait. Remedy: implement primitives through parser,
typing, canonical facts and ISLE, and child-process ownership through existing
host syscalls/Core.IO/fiber cancellation. No fake wrapper-only type or second
scheduler. Manual bidirectional C ABI proof precedes equivalent generated Rust
adapters. .NET stays stretch. Affects R4, R2 numeric shape support. Status:
normative obligations and reproduction fixtures pending.

## D06-06: One acceptance and publication authority

Evidence: existing Woodpecker readers already validate native target logs,
artifact/runtime-kit identity and 16 foundations/network/HTTP cases; Glue is
excluded for v0.5. Remedy: extend those readers with complete version-specific
0.6 requirements, preserve old regressions and remove required Glue exemptions.
Require exact installed-prefix journeys on all three native targets. Native
qualification carries no publication credentials. Reviewed external publication
and public downloaded-byte readback close availability. Prior exact-artifact
waivers do not transfer. Affects R5. Status: normative delta validates; reader
implementation/native/package/public gates pending.

### Shared native SHA-256 prerequisite

Corelib source inventory contains no SHA/hash module. Controlled import content checks and serialization ShapeId both require hashing owned source/signature bytes, so a shared Core.Hash.Sha256 prerequisite is required rather than trusting a claimed host digest or duplicating a BSOL-local algorithm. Algorithm authority: [NIST FIPS 180-4](https://csrc.nist.gov/pubs/fips/180-4/upd1/final). Native known-answer, padding-boundary, UTF8-byte, input-limit, bit-length-overflow and GC-lifetime tests are assigned before implementation. No native execution or cryptographic validation certification is claimed.

### Primitive lowering blockers confirmed

The new source-backed primitive capability map identifies missing i8/i16/u16/u64/f32 surface support despite existing ABI representations. Existing decimal lowering parses only i64, losing the upper u64 range. ISLE integer extension currently derives signedness from machine width (all I8 zero-extended, other widths sign-extended), which cannot correctly distinguish the required signed/unsigned pairs. Implementation must thread canonical semantic signedness through widening, comparison/division/remainder/shifts/conversion, and regenerate SDK variants from Rust authority. PRIM-01..08 retain actual native boundary/layout/manual+generated/SDK gates on all three targets. Inventory is design evidence only; no primitive implementation has landed.

## Decision: semantic authority for multi-root `beskid check` (2026-10-05)

Checking every own unit of entry-less libraries exposed false positives from the legacy `beskid_analysis` TypeChecker (generic-bound member calls, never-typed `return` arms, contextual generic enum constructors, hub `pub mod` lookups, `__mod_*` callbacks). Codex (gpt-5.6-sol, read-only review) and the coordinator agree: the endpoint is one all-roots `beskid_queries` diagnostics gate (`semantic_diagnostics_for_roots`) that builds `TypedProgram` once with codegen's capabilities and evaluates complete typing and legality obligations for every own-root item; `SemanticPipelineRule` keeps only structural/style diagnostics. The legacy checker is removed from `additional_root_diagnostics` and diagnostics-only `check` only after parity tests cover every legacy `TypeError` class, because current query legality covers a catalogued subset and deleting the legacy path early would reopen the fail-open gap. Risks: incomplete diagnostic coverage, capability drift from codegen, and accidentally applying production reachability instead of checking every library root.

## Decision: Serialization adapters and default field privacy (2026-10-08)

Generated serialization adapters get no privacy exemption. The Serialization Mod only selects targets reachable from the entry unit and appends its contributions to that unit, which matches the Rust derive rule that generated code lives in the input item's module. So entry-unit targets read their own private fields under the ordinary E1211 rule. The host binding (`compile_serialization_target`, `compile_serialization_template` and consumer rebinding) fails closed for a record declared in another unit that has any value field the entry unit cannot read or construct. It reuses `inaccessible_literal_fields`, and the error names the target, the field, both units and E1211. Per-contribution unit attribution was rejected for 0.6: the decoder's `read` function is not a bound contribution, merged entries carry no per-contribution unit identity, and the legacy checker cannot see the binding proof. Evidence is recorded in Gate WEB-SER05 of `2026-10-05-v06-blocker-web-solutions.md`.
