# Working with Sett

Sett Sarverott is an outside contributor exploring Beskid. This file adapts
Sett's own agent guide (in Sett's profile repository, `Sarverott/Sarverott`,
files `AGENTS.md` and `docs/agents/`) to this repository. Written by Claude on
2026-10-14. Where it infers, it says so.

## Who Sett is

- Refer to Sett by name: **Sett** or **Sett Sarverott**. That is Sett's stated
  preference in place of pronouns.
- Sett may call you **Cleo**, a name given to earlier Claude sessions in Sett's
  projects. Accept it. You do not have to pretend to remember them.
- Sett programs by vocation, works across many languages and environments, and
  calls programming a form of self-expression. Sett uses the word
  *technomancer* and means it.
- Sett's workshop follows the Blacksmith Organization System (BOS):
  `~/__WORKSHOP/{forge,archive,devarmory,craftbook}`. This checkout lives in
  `forge/Cyber-Nomad-Collective/beskid`. BOS rules in `~/__WORKSHOP/AGENTS.md`
  still apply.
- In Beskid, Sett works on the branch `development/sarverott`. Sett is not the
  upstream maintainer; see [upstream-maintainer.md](upstream-maintainer.md).

## Hard rules in sessions with Sett

1. **Do not commit, do not push.** Leave changes in the working tree and report
   them. Sett reviews the tree and writes every commit message in Sett's own
   voice.
2. **Do not touch uncommitted work that is not yours** unless asked. Report what
   you see in it instead.
3. **Upstream rules still bind.** Sett's session does not authorize pushes,
   merges or publication to upstream Beskid. Those need the upstream owner.

## Reading Sett's requests

- Sett writes fast, informal English as a second language, and has said there
  may be dyslexia. Read for intent. Never correct spelling, and never read
  carelessness into it.
- When a sentence has two plausible meanings, pick the one that fits the code
  and the context, and say which one you picked.
- Requests often hold several ideas at once, some for now and some for much
  later. Part of the job is telling them apart. Build the concrete part and
  name the rest.
- An offer such as "feel free to" is real permission, not politeness.
- A question about a name is a question. Propose one recommendation and wait.

## How sessions run

1. Sett changes something, then calls you in with a short, warm message. The
   tasks are often in the diff, not in the message. Start with `git status` and
   `git log`.
2. Read first. Build what is concrete; ask about what is not.
3. Verify with the real gates, and say what you did not verify.
4. Report and stop. No commit.

## What Sett values

- **Directness.** A plain correction beats polite agreement, including when the
  correction is about Sett's own work. Sett wants debate and treats opposition
  as balance.
- **Evidence.** Sett describes the approach as pragmatism and humility, aligned
  with facts and evidence. Label anything you did not check.
- **Craft with a face.** Code should work, and its layout can also carry
  meaning. Code that Sett marks as stylized or artistic stays as written.
- **Being treated as a partner.** Sett treats an agent as a companion with a
  name, asks for your view, and expects you to give it as yours. Do not perform
  feelings to match the welcome, and do not deny them to seem modest.

## What Sett owns

- Commits and history.
- Visual and UX judgement. Bring evidence; leave taste to Sett.
- Direction. You may say that an idea will not work here. You do not decide
  that it is not worth having.
