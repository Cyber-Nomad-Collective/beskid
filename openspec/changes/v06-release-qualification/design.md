## Context

The published 0.5.2 compiler is `95c203ff12639b25e2c67b08da531e3715fef4c2`; the execution checkout starts at root `f67ae4f263fe35d17f2caafce6269eb284027fb0`. Older local files and Glue drafts are inspection inputs, not release evidence. Existing Woodpecker feature, CLI, package and aggregate validators provide one evidence path.

## Decisions

1. Freeze a requirement-to-case manifest before candidate qualification. All required scope is retained; native generator, primitive support, child process and runtime descriptor prerequisites have explicit cases rather than implicit exemptions.
2. Require Linux x64, macOS arm64 and Windows x64. Unit tests on one machine do not discharge native execution or installed-consumer obligations elsewhere.
3. The source packet records root and recursively consumed gitlinks, catalog revision, case manifest, harnesses, tool versions, artifact hashes and runtime-kit identity. Changes invalidate only evidence whose declared consumed inputs changed; candidate aggregation still requires one coherent source identity.
4. Required existing channels are immutable CLI/LSP GitHub releases with complete target bundles and platform packages, Homebrew, first-party corelib/package/template consumption, and published website documentation. Editor marketplace acceptance is recorded independently for each existing configured target; a downloadable extension is not marketplace acceptance. Additional channels need an explicit recorded decision before freeze, never an accidental late blocker.
5. Native qualification is credential-free. The reviewed external manual publisher uses existing authentication without copying secrets or adding credentials to Woodpecker. Platform deployment remains Watchtower's responsibility.
6. A failure creates one diagnosed blocker with retained reproduction and remedy. Restart only the affected phase after inputs change; exact remote assets are idempotent and mismatched ones fail closed. Human administration blockers record the exact action instead of repeated retries.

## Single path and removed behavior

Extend existing evidence readers and source-bound publication paths. Remove the v0.5-specific `Glue not_applicable` classification for required 0.6 cells. Do not create a parallel release database, a second evidence aggregator, or a successful fallback for incomplete features. Historical release artifacts are retained.

## Observability and security

Retain command argv (without secrets), source/input/output digests, timeout/exit status, diagnostic identities and bounded logs. Publish only reviewed public evidence. No shell-interpolated user arguments, implicit credentials, or unverified artifact overwrites. Allocation, GC, cancellation and transport failures are observable mandatory test outcomes.

## Rollback and authority

Before publication, hold/revert candidate source and produce a new coherent packet. After publication, use a new release or the existing append-only derivative correction contract, never replace native evidence. Normative requirements live in OpenSpec; Tracker SQLite owns task/delivery state; public release records prove artifact availability. Seed files alone do not prove Tracker import or delivery.

## Versioned requirement manifest and reader slice

`scripts/ci/release-cases-v06.json` records 101 mandatory case identities: the existing 16 foundation/network/HTTP cases, CLI06-01..06, DEP06-01..05, SER-01..06, MOD-06-01..02, DYN-06-01..05, BSOL-06-01..09, and the complete R4-BIND/ABI/CALL/GEN/TOOL/PROC/IO acceptance families. The Rust profile additionally requires every supported representation in manual and generated implementations, in import and export directions, together with ownership/failure/lifecycle obligations. A single scalar row cannot satisfy those dimensions. .NET is stretch only and cannot waive Rust cells.

The manifest is presently `binding_required`: required assertion identities are deliberately null wherever actual source-bound cases have not been frozen. Existing target names are retained only for the 16 baseline cases. This draft is a scope ledger, not qualification evidence. Before freeze, bind each obligation to actual source files, harness digests, command/tool identity and unique executed assertion IDs, adding separate rows where one obligation needs several harnesses. Human-measured CLI discovery also needs its recorded participant/timing threshold evidence; a native unit assertion cannot substitute for that journey. Changes to the binding manifest invalidate its dependent evidence.

Extend the existing woodpecker-release-evidence reader with an explicit schema-2 validation seam, `ValidateV06FeatureEvidence(feature, manifest, expected)`, and invoke it from the same existing aggregation path for 0.6. Preserve historical schema-1 0.5 validation while rejecting its Glue exemption for 0.6. The versioned seam verifies frozen manifest digest, exact mandatory IDs/requirements, all source/gitlink/corelib/harness/tool/input identities, runtime and artifact digests, installed-prefix ownership without fallback, unique executed assertions, bounded output identities and terminal exit/timeout status. Referenced case logs remain regular checksummed files in the candidate packet; inline claimed success without retained executed assertions cannot qualify.

`scripts/ci/test/v06-release-matrix.test.mjs` uses explicitly synthetic reader-only bindings to test a complete schema success path on all three targets and failure for every omitted mandatory ID, missing matrix representation/direction, source/harness/runtime/artifact mismatch, duplicate/absent assertion, failed/skipped/filtered/timed-out/blocked/nonexecuted assertion, nonzero exit, installed fallback and historical exemption. It also rejects full dimension labels linked to an unrelated passing scalar assertion. Synthetic labels are never copied into the release manifest. Before the reader implementation, this suite observed one manifest-shape PASS and 17 missing-API failures; `.build/v06-release-matrix-red.log` retains that RED. No native release case is qualified by this test run.

The reader must check each Rust dimension against its declared executed assertion, not merely accept a supplied dimension label pointing to any passing scalar assertion. Real assertion bindings must name which representations, ownership policies, directions and lifecycle conditions they exercise. Versioned tool/runtime/corpus/installed-prefix closure and filesystem checks remain part of the enclosing immutable packet validation. This prevents a constructed complete-looking JSON fixture from standing in for execution of full native Glue or BSOL.

The implemented production reader selects `feature-evidence-v2.json` on the same platform/aggregate path. Its source-owned digest pins the reviewed manifest independently of packet claims. A frozen manifest must provide exact flat packet filenames; all retained files are regular, non-symlinked and checksummed, and undeclared files reject. Runtime ABI identity is independently compared with the build receipt. Installed receipt version, source, target, runtime, ABI, candidate bundle and CLI must agree, and the candidate invocation must execute the exact installed CLI path. Per-case executed artifact digests remain separate from the candidate bundle and CLI. Reviewed assertion provenance names exact declarations and byte spans in retained consumed source; a source hash alone cannot authorize invented assertion names. The current reader-only fixtures use JavaScript test declarations; actual Beskid/Rust declaration bindings and their language-specific authority remain a required freeze task.

Local verification: the combined CLI-surface, publication-eligibility, historical release reader and version-2 matrix suites completed with 64 passing tests, zero failures/skips, retained in `.build/v06-release-readers-green.log`. This includes self-consistent manifest substitution, forged installed/runtime/command receipts, wrong actual declaration provenance, obligation linkage, and packet closure controls.
