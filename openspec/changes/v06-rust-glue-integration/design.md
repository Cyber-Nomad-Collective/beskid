## Decisions

1. Delivered Rust Glue is one in-process call path: the Beskid consumer image calls Rust owner images through checked C ABI status/out-parameter wrappers. Each binding is a generation-bound Glue binding fact (`GlueBindingFact`, `GlueLogicalType`) with backend/library/symbol/direction/target/ABI/layout/call/ownership semantics, formed before generation. Manual C ABI probes establish representation independently; generated Glue reproduces them. The stdio bridge is a separate provisional capability (`v06-glue-stdio-bridge-provisional`) and is not a delivered transport. Glue generation does not invoke Mod contracts; the 0.4 contracts, attributes and `mod.glue` phase are deleted.
2. Support i8/i16/i32/i64/u8/u16/u32/u64/f32/f64 through genuine parser, semantic/query, typed AST, ISLE and runtime prerequisites. Scalars never use fabricated wrapper-only source types. Bool is checked u8; char checked u32. Views are pointer/uintptr_t length inputs and owned bounded views for managed returns. Explicit release operation transfers ownership; no allocator assumption.
3. Stdio protocol v1, its limits and its pump/session design moved with the stdio bridge to `v06-glue-stdio-bridge-provisional`. The delivered path bounds owned views at 16 MiB and checks them before effects.
4. The Glue value-format adapter over the shared generic codec interface belongs to the provisional stdio bridge. The delivered path preserves IEEE bits including nonfinite and -0 across the checked C ABI, and handles cross only as branded checked tokens.
5. Tool discovery uses explicit path XOR prefix, direct argv (no shell), 10 s probe deadline and 1 MiB output cap. Record all observed hashes, versions and target compilation evidence; check pin if configured and recheck binary before spawn. Stable artifact identity excludes machine-local paths/time/logs but retains portable tool identity and relative files/digests/closure. Secure atomic materialization rejects escape/duplicates/symlink escape. Current state: the Rust owner build pins the cargo, rustc, linker and driver SHA-256 and rechecks them before use (`beskid_aot/src/api/glue/rust_owner.rs`); the general `beskid_abi::toolchain::probe` still verifies file presence only, so the version, target, deadline and output-cap probe remains open (task 2.4).
6. Child process capabilities reuse Core.IO Reader/Writer partial semantics and the canonical host syscall table as general Core.Process services. Rust panics caught inside compatible wrappers become declared errors; abort/trap is process failure; no foreign unwind crosses C. All setup failure/exit paths release owned resources once.
7. `beskid build` inputs (WEB-GLUE01, docs/reports/2026-10-05-v06-blocker-web-solutions.md). The manifest declares owner identity and the source location: `glue "<library>" { backend = rust path = "<dir>" }`. This follows maturin/napi-rs. The consumer identity is the target name, following the Cargo lib-name default. Item mappings live in Beskid source as the closed `RustOwner` attribute on `GlueHandle` types (Path required) and Extern contract methods (Path default `implementation::<symbol>`, Fallible default false). This follows the declaration-site and Result-in-signature precedent of UniFFI and cxx. Paths must start with `implementation`. The owner package is compiler-generated with no third-party dependencies in 0.6. Tools come only from `--rust-toolchain` XOR `--cargo`+`--rustc`, plus `--linker`; `CARGO`/`RUSTC`/`PATH` are never read. Cargo runs with the inherited Cargo/rustc/rustup environment removed, an empty staged `CARGO_HOME`, and a rejection of ancestor `.cargo/config*`/`rust-toolchain*`. Outputs are staged and published atomically. glue-dotnet fails closed.
8. Fallible imports. An import declared `[RustOwner(Fallible:true)]` and every export whose direct-call closure reaches one are fallible packet rows, and fallibility is part of the row identity. The checked invocation of a fallible export roots a failure cell, enters a runtime checked scope and calls the checked effect counterpart of the export body. A fallible import adapter records the first nonzero owner status in that scope and returns its zeroed output; the invocation then returns that status. A non-fallible import failure, or a fallible import failure outside the scope or through the direct export symbol, traps (`beskid_codegen/src/checked_effect.rs`, `beskid_codegen/src/glue/native.rs`).
9. Owner records belong to the runtime of the thread that opened it. A release from that thread during a live borrow returns Busy; a release from another operating-system thread returns Foreign. Neither runs the destructor or consumes the token (`glue_owned.rs` borrow tests, R4-OWN-14 and R4-OWN-19).
10. The modified Process execution contract (D-CORE-PRIM-0180) is rebased on the current base requirement. It keeps the stable ID `BSP-REQ-4A7C91E2D6F308B5` and the base scenario "Conformance exercises Decision". The migrated quote that `Run` delegates to `__process_run` is replaced, because 0.6 `Run` uses the same Spawn, pipe, wait and cleanup authority as `Spawn` and has no separate dispatcher.

## Implementation and Conformance Anchors (Informative)

### Compiler-issued native admission

`beskid_aot::api::glue::PreparedGlueArtifact` is a private, non-deserializable authority. Its producer `build_glue_artifact` accepts the current registered `CodegenInput`, complete and selected canonical item keys, native library identity, expected generated packet, runtime build request, explicit adapter compiler, output path and execution control. It performs canonical body lowering, object emission, exact generated adapter C compilation and typed linking itself. Private issuance consumes the resulting sealed source/object/native witness; caller-supplied `LinkResult` cannot issue admission. It regenerates the packet from the current assembly and compares every file and binding; a self-consistent substituted JSON packet is insufficient. The runtime build request is independently resolved again because the public `RuntimeArtifact` DTO alone cannot establish its provenance. Only the exact validated shared provider profile is accepted.

Issuance pins the final native payload bytes, exact linker executable and receipt, target ABI, canonical issuer source, shared provider image and platform import payload. Bounded parsing of the actual ELF, Mach-O or PE loader tables verifies the dynamic dependency on that provider; a static duplicate or competing provider fails admission. Installation can relocate validated payloads without requiring the original build machine paths; portable identities remain framed source/file digests, whereas local retained handles retain canonical paths.

The AOT producer owns staging/link/publication; CLI callers consume its private witness. The shared loader rechecks the current compiler packet, payload and provider closure, then pins the provider and foreign image before obtaining provider-owned admission. Registration binds the full compiled signature, declaration identity, generation, library and constructor/reader/transform callback addresses. Generated wrappers may look up already admitted identities, but cannot publish their own constant JSON as proof. Admission lifetime covers every callback and managed value originating in the image; failed setup rolls back roots and native handles exactly once.

The generated native image exposes `beskid_glue_artifact_v1_initialize`. Its borrowed V1 admission table contains version, byte size, host context and a synchronous checked admission callback. The callback compares the exact compiled source digest and complete bounded shape identity list against the private producer witness, registers the compiled closure with the canonical provider, and returns a nonzero library token. The table is not retained. Initialization transitions atomically from uninitialized to initializing to ready, or restores uninitialized after failure; checked wrappers reject calls before ready. Neither a supplied token nor a caller-rehashed packet can bypass host admission. The loader owns the table's authority and the source generation; the generated image cannot invent an epoch.

Required regression controls include substituted packet with recomputed checksums, stale assembly generation, changed payload after linking, forged runtime DTO, modified linker executable, missing or duplicate dynamic provider dependency, callback address outside the pinned image, and release after unload or provider replacement. Missing APIs are separately recorded as prerequisite RED and never qualify native execution.
