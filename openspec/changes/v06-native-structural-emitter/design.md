## Context

NativeContractInvoker previously loaded libraries then delegated Generator to StubContractInvoker. The observed real dylib regression failed because its entry marker never appeared. ModSyntaxNodeHandle is an opaque pointer field; it must be a validated lookup token, never a pointer cast to Rust AST. Context compilation hardcodes syntax generation0; merge pipeline hardcodes1.

## Decisions and Concrete ABI Proposal

All required native targets are64-bit, little-endian. Rust repr(C) ABI size/offset tests freeze the following tables before implementation; these are Mod host interfaces, not runtime kit layouts:

- ModStructuralGenerationRequestV1: abi_version:u32 at0 (=1), struct_size:u32 at4, legacy_context:ModGenerationRequest at8, emitter:ModStructuralEmitterV1 following that complete unchanged context, semantic:ModSemanticHandle following emitter. ModGenerationRequest currently184 bytes; proposed emitter40 and semantic16 yield request248, alignment8. Tests compute/assert actual size/offset rather than assuming this prose proves layout.
- ModStructuralEmitterV1: version:u32 at0 (=1), struct_size:u32 at4 (=40), host_context:opaque pointer at8, syntax_generation_id:u64 at16, define_unit_function callback at24, define_record callback at32.
- Callback return ModStructuralResult: status:u32 at0, kind:u32 at4, node:ModSyntaxNodeHandle at8; size16/alignment8. Status0 means success with checked nonzero token; nonzero errors carry no node.
- Callback requests carry struct_size/version, requested syntax generation, name:BeskidStr, source span(u64 byte endpoints and line/column endpoints), and record generic-name/field-spec slices. Fields identify either approved primitive type or an explicitly declared generic parameter with semantic query authorization required before lowering. Strings/counts/depth have hard bounds and are copied within callback; no source program text is accepted.
- Artifact exports beskid_mod_structural_generator_abi_version()->u32 exactly1 and a separately named structural entrypoint. Host validates marker and required table size/version before calling ModStructuralGeneratorEntryFn. Missing/wrong marker rejects required structural generation; no signature guessing or legacy stub supplies success.
- Semantic field is existing ModSemanticHandle, pointer to a read-only v1 query table or version0/null if unavailable. A missing query fact/capability fails when needed; source reflection and HIR rebuild do not substitute. Root semantic owner freezes the query table separately and binds it to the same generation/owner.

Host-owned arena stores canonical static AST, validated provenance and owner/generation. Opaque IDs are monotonic and never reused, map lookup only; foreign/stale/closed/kind mismatches reject. Callback host_context is likewise an opaque lookup token with invocation-scoped live registration; callback cannot dereference retained context after return. No pointer-to-AST cast or source parsing.

Constructor v1 demonstrates real native creation of function and generic record nodes. It is a bounded prerequisite; full serialization additionally needs semantic eligibility/query facts and complete expression/type/extend adapter constructors. Native output is validated/materialized atomically then merged through existing typed pipeline and semantic authority. Generated provenance survives outcome/merge.

## Generation Handoff

ModHostInput carries Option<SyntaxGenerationId> from actual ProgramAssembly/current Salsa generation. Production spine and query Mod host pass it; absence explicitly means unavailable and cannot authorize required native generation. Context and pipeline consume that identity; no invented0/1 epoch. Standalone test stubs can have absent authority, never masquerading as native structural capability.

## Observability and Security

Contextual typed error includes package/contract/type/generation; no payload secret logging. Hard arena limits:4096 items,65536 AST nodes,depth128; explicit callback name/scalar cap1MiB and slice cap4096. Validate before allocation/publication; no native context token reuse. Source-bound native fixtures live under disposable .build and compile/execute a real dylib.

## Registered Semantic Authority Extension

The analysis crate cannot depend on beskid_queries because queries already depends on analysis. The proposed read-only trait and owned shape DTOs therefore live at the analysis Mod boundary, while ModSemanticQueryAuthority in queries implements the trait using the existing registered Salsa semantic contracts. No second shape registry/cache, parser, semantic pass or HIR adapter is introduced.

The authority constructor is `ModSemanticQueryAuthority::for_registered_assembly(&db, project, &assembly)`. It derives its generation from the actual ProgramAssembly; it has no caller-supplied generation override. Every assembly source unit must already belong to that project and current generation in the canonical database. `resolve_type(AstNodeKey)` is the checked issuer boundary: it validates source-unit registration, owner, generation and TypeDefinition kind before returning an opaque authority-issued handle. The analysis trait exposes `generation()` and `type_shape(issued_handle)`; it never treats an unchecked key or address as proof. Handles are issuer-bound as well as generation-bound and expire with their authority/invocation.

Shape DTOs preserve declaration source/node/generation identity, source-facing name, exact applied type arguments, ordered field declarations/names, primitive or nominal type identity, and GcManaged/NativeOrScalar ownership. Native-or-scalar classification is a source fact; pointer-shaped ABI storage cannot establish managed ownership. The implementation delegates to aggregate_layout, applied-generic source identity/substitution and managed-reference queries. Existing aggregate layout alone erases applied nominal arguments, so it is insufficient as a substitute for the complete identity. Unsupported shapes remain unavailable; the separate complete primitive capability requirement remains authoritative for missing widths/f32 rather than inventing IDs here.

The first authoritative integration test builds a real filesystem source project with assemble_program_with_materializer, obtains its allocated generation, registers the same assembly through build_typed_program, then queries primitive, nested string-bearing nominal and Box<i32> fields. Negative cases cover stale generation, unknown unit, foreign owner, non-type key and foreign issuer. No hand-assigned generation initializes the assembly. The only altered generation appears as an intentional stale-input rejection control.

Canonical expression wrappers must preserve the same current field facts used by a direct path query. The native BSOL trigger `value.span.end - value.span.start` exposed a wrapper seam: direct PathExpression queries enter nominal_field_projection, but abi_type_for_expression(Path) currently normalizes the key and calls a narrower local-path helper that rejects three-segment chains. A real materializer regression using the exact Core.Bsol.Syntax source checks path controls, operand wrappers and binary ABI before implementation. The remedy must consume the existing generation-bound query, not inspect AST fields to invent a type or reconstruct HIR.

The semantic native table is not guessed or appended to the constructor V1 ABI. Its exact table layout/version/limits and issuer lookup protocol require independent frozen ABI tests before implementation. Existing semantic version0/null stays explicitly unavailable until that table is implemented; it does not enable a syntax-only fallback.

### Concrete Rust seams and bounded traversal

`beskid_analysis/src/mod_host/semantic.rs` owns the shared read-only trait, opaque Copy handle with private issuer/slot fields, shape DTOs and typed errors. `resolve_type(AstNodeKey)` remains an adapter method in queries so analysis acquires no dependency on queries. `beskid_queries/src/mod_semantic_authority.rs` borrows the database and registered assembly/project for the authority lifetime. Its issuer-local handle table retains canonical declaration/application identities only; it does not retain a second shape cache. Every lookup rechecks the registration and current generation before querying facts.

The constructor must check every assembly unit against its registered SyntaxUnitInput project, generation and expanded syntax/index identity. `typed_program.rs::registered_syntax_owner` is useful existing ownership context but is insufficient by itself: it deliberately skips unregistered units. Partial registration must therefore fail rather than grant an authority over the registered subset. Issuer IDs must not be reused after authority closure.

`semantic_contract/mod_shapes.rs` provides the Salsa-backed projection within the existing semantic authority. It reuses `calls/generics/source_identity.rs::generic_source_type_identity_with_substitutions`, existing type declaration resolution, `layouts/aggregate.rs::aggregate_layout_from_definition`, and `GenericSourceTypeIdentity::managed_reference_kind`. Primitive source identity must remain exact; ABI-equivalent or pointer-shaped facts alone cannot recover a source type. Unsupported identity projections fail closed.

Applied nominal handles retain exact canonical declaration and declaration-ordered type arguments. Arity mismatch, missing substitution and unapplied generic field types reject. Shape lookup emits child nominal handles without recursively expanding their fields, so ordinary self-referential nominal shapes terminate and retain their identity. Substitution traversal has explicit depth/node bounds and detects cyclic substitution expansion; it returns an unavailable/limit error instead of manufacturing a type or overflowing the stack. Array element identities use the same canonical source identity; unsupported associated or function shapes remain unavailable until their own complete contract is implemented.

## Full Adapter and Provenance Extension

Beyond the observed UnitFunction/generic-record prerequisite, the next constructor surface must represent primitive/composite/applied types, parameters/results and real field access/calls/literals/result propagation/function bodies. A generated adapter must call the canonical Encode/Decode interfaces on actual source fields and pass semantic validation. Extending the constructor table requires an explicit new version/capability, not appending fields to frozen V1.

GeneratorOutcome and typed merge must carry ordered generated-item metadata alongside the canonical AST nodes: source-unit origin, actual origin generation, generator registration and origin span. Arena-only metadata is insufficient. Subsequent semantic registration uses the new current assembly generation and node identities while retaining origin lineage separately; an old origin AstNodeKey must never be passed off as a current registered key. Merge validates metadata/item count and identity atomically before publication.

## Compiler-built executable Mod prerequisite

The production seam is currently incomplete: `beskid_aot/src/mod_artifact.rs::build_mod_artifact` always uses `emit_object_only` and writes schema-1 `objectFile: mod.o`. The analysis descriptor mirrors that field, and `mod_host/native.rs::ensure_loaded` passes its path directly to libloading. Registration extraction only names `package_generate`; it does not emit a structural C trampoline or ABI discriminator. A linker-only switch to SharedLib would therefore expose an incompatible Beskid method as the frozen structural entry rather than implement the contract.

The next backend slice must issue a separately versioned executable-artifact descriptor with explicit artifact kind, exact host target, structural ABI version/capability, entry/discriminator symbols, source/tool/runtime-kit identities and checksummed output closure. Keep an intermediate relocatable object only as build evidence, never as an executable Generator. Both descriptor readers must reject incompatible kinds/versions before dispatch. The cache key must include the emitted ABI and runtime/tool identities, and publication must follow successful linking/export validation atomically.

Codegen must emit a C entry trampoline with exactly the frozen request signature and an exported discriminator. The trampoline validates version/size/generation/context before adapting the canonical source-level SDK request and invoking the actual Generator implementation identified by the registration. Each registration needs an unambiguous callable identity; several types implementing Generate cannot share a guessed package-only entry symbol. A new callback/semantic/runtime context extension, if needed, must be separately frozen with ABI offsets and lifetime tests before use, without appending fields to V1.

Canonical SDK node construction and return values must cross the boundary as checked structural operations into the invocation-owned host arena. Native managed SDK objects cannot be cast to Rust AST pointers. The translator must consume the generated authoritative node schema and preserve every supported field and provenance; unsupported shape or SDK/schema drift fails closed. The present V1 callbacks support only a unit function and generic record prerequisite, so they cannot silently truncate a richer FunctionDefinition or qualify full serialization/Pest emission. The source SDK currently uses u64 while canonical PrimitiveType lacks U64, and its FunctionDefinition mirror omits Rust where_bounds/spanned metadata; resolve these existing language/schema prerequisites before claiming canonical SDK execution.

Generated code that allocates SDK values needs the exact canonical runtime kit and shared runtime attachment/GC lifetime. Linking a second independent runtime or scheduler is not an acceptable way to execute the Mod. The existing AOT SharedLib/library-pair machinery is the linker seam; define and test attachment, thread entry, root ownership and detach around the actual invocation before enabling managed source Generator execution.

The first end-to-end RED fixture belongs in `beskid_tests_mods` beside rebuild tests and must use a disposable real Mod project importing the actual compiler-sdk, with Generate constructing a new public unit FunctionDefinition through Emitter.Nodes/Items/Contribution. It must invoke the production compiler/AOT build route, inspect the descriptor's executable kind and exported discriminator, load that resulting library through NativeContractInvoker, materialize the new host AST item, re-register the merged assembly at its actual generation and compile/invoke the generated function. No Rust/C handwritten substitute library, redeclared SDK lookalike, prepared host token or text parser can satisfy this fixture. Capture failure separately at SDK compilation, artifact production, exported ABI, native invocation and host materialization so a missing prerequisite cannot masquerade as a runtime execution result.

After that minimal fixture passes, retain negative tests for wrong target/ABI, missing or drifted tool/runtime kit, absent discriminator, duplicate generator entry identity, SDK/schema mismatch, foreign/expired generation/context and allocation/panic failure. Current Pest Emit.BuildAll returns only codeOutputs containing RegexGeneratedHeader source text; executable-library delivery alone must not mark typed structural Pest generation complete. Convert Pest and serialization adapters through the full typed constructor/body surface in their later explicit delivery gates.
